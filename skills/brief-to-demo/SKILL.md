# ひと言から、作れる依頼へ

曖昧な依頼を、そのまま制作へ渡せる短いブリーフにする。相手の意図を保ち、足りない製品機能・測定値・実績を作らない。

入力は紹介したいスキルの原典、利用者がしたいこと、使える素材。出力は次のJSON。推測した条件は `assumptions` に分ける。

```json
{"title":"依頼の題名","request":"元の依頼","category":"ui-ux | slides | motion | agents","audience":"誰が見るか","goal":"達成すること一つ","inputs":["実際に渡す素材"],"skill_refs":["読むSKILL.mdまたは固定原典URL"],"deliverables":["開ける成果物"],"steps":["素材から成果へ進む操作"],"acceptance":["利用者が確認できる完了条件"],"assumptions":["未指定の条件"]}
```

カテゴリは成果物から選ぶ。UIなら操作できる画面、スライドなら実際に開く資料、モーションなら書き出した映像を完了条件にする。調査・整理なら実入力と整理結果を対で残す。

既存プロジェクトがある場合は、その正本とスキルを先に選ぶ。便利そうな名前だけでスキル適用済みとしない。原典を読んだだけ、コードを実行した、成果物を見た、を制作記録で区別する。

サイト用の短い動画は「元の依頼 → 選んだ制作方法 → 実際の結果」で組み立てる。サンプルだけを再生するページに、ライブAIが動いている表示を付けない。
