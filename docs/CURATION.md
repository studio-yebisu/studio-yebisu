# 分野別の紹介を追加する

分野の定義は `data/categories.json`。用途で分類し、スキル・ライブラリ・MCP・アプリ・教材などの種類は `kind` で示します。分野を増やしても、専門制作のリポジトリやCodexプロジェクトを増やす必要はありません。

## 紹介と制作した作例

- 原典を読んだ紹介は `data/curated-resources.json`。`verification_stage: source-reviewed` を付け、用途、試し方、必要な環境、依頼文、利用条件、原典の固定コミットを記録します。
- 実際に制作した作例は `data/cases/<id>.json`。実入力、結果、操作できる作例、動画、再現手順と確認記録を揃えます。同じ紹介を発展させる場合は、作例の `catalog_entry` で同じIDを引き継げます。

紹介だけの項目に、実行済みの印象を与える作例画像・動画を付けません。作者が示す能力・測定値と、Studio Yebisuで確認した範囲を分けます。

## 原典と利用条件

公開投稿は発見の入口とし、本文の説明は元のREADME、SKILL、コード、LICENSEを確認してまとめます。保存一覧や個人の履歴は公開データへ含めません。

リポジトリ移転と既存項目の重複を確認します。スキルの集合から一つを紹介する場合は対象パスを残します。コードのライセンスだけで、モデル重み・フォント・画像・音声・クラウド・生成物の条件まで同一とみなしません。名称に企業名が含まれていることだけで公式と判断しません。

最初の依頼文は、具体的な入力から結果を確認するところまでを書きます。環境やモデル要件を先に確かめられる内容にし、存在しない結果を作例として記録しません。

## サイトへの反映

```powershell
python scripts/build.py
python scripts/check.py
python scripts/serve.py
```

ビルドは既存プロジェクトのスナップショット、追加紹介、完成した作例を統合します。`scripts/sync_catalog.py` は既存プロジェクトの再取り込み専用で、追加紹介を上書きしません。

ブラウザーでは分野の直接リンク、検索、種類の絞り込み、件数、詳細、依頼文と出典を確認します。公開が依頼済みの範囲は対象ファイルを限定して反映し、実際のURLを確認します。
