# コードのつながりを、地図に。— 32秒・無音の概念図ムービー（編集ソース）

Codebase Memory MCP 作例の解説動画の編集ソースです。1枚の図（コードの束 → 手で回す索引の橋 → 呼び出しの地図 → 実際の記録の保存先）を、同じファイル・同じ関数カード・同じ線・同じ変更の印のまま動かします。文字のスライド、ページのスクリーンショット、ナレーションは使いません。

- 長さ：32秒・30fps・960フレーム
- 寸法：縦 720×1280（主）と横 1280×720。どちらもその寸法で配置を組み直して描きます（縦に横長の画面を入れた額縁にはしません）。ほかの寸法は、高さ > 幅なら縦、それ以外は横の配置を拡大縮小します。
- 音：無音。`audioEvents: []`。ナレーション・読み上げ・効果音・音声トラック・字幕原稿はありません。書き出しにも `--audio` や `--synth` を付けません。
- 場面の時刻と見出し：`assets/timeline.json`（固定）。各場面の入り・状態・変化・出・元データは `storyboard.json`。

| 時刻 | 場面 | 図の変化 |
| --- | --- | --- |
| 0–5秒 | 全体 | コード・索引の橋・地図（線4本）・保存先がつながった全体 |
| 5–10秒 | 索引する | 取っ手が回り、各ファイルの写しが橋を渡って関数カードになる。最後に4本を同時に引く |
| 10–15秒 | 探す | submit_order と service.py を強調。実際の8行目の def と「8–19行」 |
| 15–20秒 | たどる | 同じ submit_order から並んだ3本（9・10・18行）を同時に強調。「順番ではない」 |
| 20–24秒 | 変更・未更新 | storage.py に変更の印。コードは「変更後」、地図は「初回のまま」。地図に新しい線は出さない |
| 24–28秒 | 手で更新 | 取っ手を回すと印が橋を渡って audit_receipt のカードになり、save_receipt → audit_receipt（15行）が現れる |
| 28–32秒 | 保存 | 記録が保存先へ。隣に別の箱で Python の別の実行（領収 2,400円・監査一致）。29.4秒以降は静止 |

下端の「線＝静的な呼び出し · 実行の流れではない」は全時刻で表示します。線の上を注文やお金が流れる表現、確認→計算→保存の実行順の表現はしません。

## 素材（7つ・固定）

`video.js` は描く前に `assets/manifest.json` を取得し、その生のバイト列の SHA-256 が
`e015e3ddc03445b9cedf70f1254f557421dac65b477448c4852233cf0cf27fab` であることを確かめます。続けて manifest に載った7つのJSONの長さと SHA-256 を照合し、内容どうしの整合を確かめてから `window.motionReady` を解決します。1つでも合わなければキャンバスを消し、エラーと「読み込み直す」を表示し、操作を無効にして `motionReady` を失敗させます。

| ファイル | 図での役割 |
| --- | --- |
| `runs.json` | 公式CLIの実際の要求と応答（18回）。定義行 8、呼び出し行 9・10・18・15、組の数 6・6・7、新しい線が手で再索引した後だけにあること、watch.watched:false、Python の別の実行 |
| `samples.json` | 3つの記録（探す・たどる・更新）。runs.json の要求・応答と一致することを確認し、保存先の記録名に対応させる |
| `fixture-data.json` | 架空リポジトリの本文。本文から長さと SHA-256 を計算して照合し、ファイルの中の線の長さと、吹き出しの8行目に使う |
| `diagram-data.json` | 関数カードの短い役割名（入口・注文をまとめる…）と描く線（4本→5本）。runs.json の組と行に一致することを確認 |
| `timeline.json` | 7場面の時刻・見出し・操作・段階（32秒・30fps・無音） |
| `upstream.json` | 原典の版（v0.12.0）・固定コミット・MIT・範囲。下端の版の表示 |
| `original-verification.json` | 以前（28秒版）の確認記録。呼び出し回数 18、組 6・6・7、合計 2,400円、監査一致の突き合わせだけに使う履歴で、この32秒版の確認ではない |

フォントは端末のシステムフォント（ヒラギノ・游ゴシック／游明朝・メイリオ・等幅）だけを使い、外部のフォント・CDN・AI・音声は読みません。

## 時刻の契約

- `window.motionConfig = { duration: 32, fps, width, height, posterTime: 31, audioEvents: [] }`。初期化時に `window.renderConfig` の `width`・`height`・`fps` を反映します（既定は 720×1280・30fps、`?size=wide` で 1280×720）。
- `window.motionReady` は7つの素材の確認とフォントの準備が終わってから解決します。
- `window.seek(seconds)` は 0〜32 に丸めた時刻だけから1枚を描きます。毎フレーム `ctx.save()` → 全体の消去と描画 → `ctx.restore()` を行い、呼び出し順・壁時計・前のフレームの結果を使いません。乱数は使いません。`seek(19.2)` も `seek(32)` も、その時刻の完成した画を描きます（32秒は完成した最終状態）。
- `window.__MOTION_RENDER__ === true`（または `?render=1`）のときはキャンバスだけを画面いっぱいに出し、プレビューの再生を動かしません。CSS のアニメーションは使っていません。

## プレビュー

作例フォルダで `python -m http.server 8000` を起動し、`http://127.0.0.1:8000/video/` を開きます（file:// では素材を読めません）。一時停止の状態で開き、再生・一時停止・最初へ・最後へ・もう一度再生、0〜32秒の位置、7つの場面ボタン、縦／横の切り替えが使えます。動きを減らす設定では自動再生せず、場面ボタンは各場面の完成した状態を表示します。

## 書き出し（制作側が行う）

同梱の Motion Reel レンダラー（`../tools/motion-reel/render.mjs`、Node.js 20 以上・Chrome・FFmpeg/ffprobe）を使います。初回だけ `tools/motion-reel` で `npm install --ignore-scripts` を実行します。出力先は毎回、作例フォルダの外の新しい空のフォルダにします。作例フォルダ（`video/` の親）で：

```text
python render-visual.py --out <空のフォルダ>/portrait --width 720 --height 1280 --strip-at 25.5
python render-visual.py --out <空のフォルダ>/wide --width 1280 --height 720 --strip-at 25.5
```

`render-visual.py` は作例全体の一時コピーから同じ同梱レンダラーを呼び、縦横比を明示して書き出します。元の `render.py` は互換用に保全し、縦横比の引数を受け取らない旧入口です。音の指定（`--audio`・`--synth`）は付けません。レンダラーは同じ時刻を別の順序と新しいページで描いて PNG の一致を記録しますが、これは同じ環境での再現性で、別のOSやフォントで同じ画になる保証ではありません。
