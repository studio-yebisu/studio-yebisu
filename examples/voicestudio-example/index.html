    • 実行後の /engines は、新しく作られた選択オブジェクトとして not_loaded を返しました。準備の表示は実行の証拠ではありません。実行の証拠は、成功した3回の CLI／HTTP の呼び出しと元のログです。

    していない・確かめていないこと

    • Electron の画面、既定の OmniVoice、音声合成、声のクローンとデザイン、日本語、マイク、ショートカット、テキスト挿入、翻訳、吹き替え、話者分離。MCP と WebSocket ストリーミングは capabilities に載っているだけで使っていません。

    verbose_json の seek・tokens・temperature・avg_logprob・compression_ratio・no_speech_prob は、認識エンジンが返さないためルートが既定値（0 や空の配列）で埋めたものです。信頼度や設定を測った値ではありません。1回ずつの経過時間（この入力では ）は、起動・読み込み・待ち・推定をすべて含み、速さの比較には使えません。

    図の流れを文章で読む
    1. 手順書：VoiceStudio が公開している Markdown のエージェントスキル（SKILL.md）。接続の確かめ方と文字起こしの呼び方が書かれています。
    2. 依頼：3本の WAV の場所と条件、比べるための参照文（inputs/jobs.json）。
    3. 作者AI（1体）：手順書と依頼を読んでクライアント run_example.py を書きます。実行はしません。
    4. 担当者：フルチェックアウトの中で原典CLI backend.speech_client を実行します。
    5. ローカルAPI：POST /v1/audio/transcriptions（127.0.0.1:3900）が WAV と条件を受けます。
    6. 選択と準備：元のアプリが利用条件と導入済みのモデルを確かめ、FasterWhisperBackend を用意します。
    7. 認識モデル：別物の faster-whisper-base が、音声から文字と時刻を推定します。
    8. 返答：2つの推定区間と全文が verbose_json で返り、CLI の出力をそのまま JSON に、text に改行を足して TXT にしました。
    9. 照合：送っていない参照文と、最後に文字どおり比べます。
