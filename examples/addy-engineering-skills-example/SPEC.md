# Spec: 工房のTODO — 期限の絞り込み

> 合成データの作例。架空の工房のTODO6件（`seed.json`）と既存コードは制作担当が用意したもので、実在の顧客や業務のTODOではない。
> この仕様は人との対話や段階承認を経ていない。曖昧な点は `input.md` の「制作担当の事前の決め方」で制作担当が決めたものを採用し、残りは本書の「未確認の確認事項」に挙げる。

## 1. Objective（目的）

工房のTODO一覧で、「期限が指定日まで」のTODOだけを表示できるようにする。今日やるべきこと・遅れていることを、既存の状態の絞り込みと組み合わせて一目で確認するため。

- 利用者: このページを開いた閲覧者（ログインなし、1人で使う想定）。
- 追加する能力は **期限の絞り込み1つだけ**。不正な日付の検証はこの絞り込みの入力契約の一部で、独立した機能ではない。
- 成功の姿: 指定日（当日を含む）までに期限があるTODOが入力順のまま表示され、指定を外すと従来どおり全件に戻り、既存の追加・完了切替・状態の絞り込みは変わらない。

### 制作担当が決めた前提（人への確認は行っていない）

| # | 曖昧だった点 | 決定 |
|---|---|---|
| A1 | 「期限で絞り込む」の意味 | 期限が指定日 **以前（当日を含む）** のTODO。範囲指定や「指定日ちょうど」は扱わない |
| A2 | 日付の形 | `YYYY-MM-DD` の暦日文字列。時刻・タイムゾーンは持たない |
| A3 | 基準日 | 自動の「今日」ではなく、入力された暦日。作例の代表値は `2026-10-15` |
| A4 | 受け付ける範囲 | 年1000〜9999のグレゴリオ暦で実在する日だけ（閏年を含めて判定） |
| A5 | 期限なしのTODO | 期限の絞り込み中だけ除外。絞り込みなしなら従来どおり表示 |
| A6 | 状態との関係 | 状態（すべて/未完了/完了）の絞り込みと同時に効く（AND） |
| A7 | 並び | 入力順を保つ。期限順に並べ替えない |
| A8 | 指定なし | `cutoff` が `null`・空文字・省略なら絞り込みなし |
| A9 | 不正な指定 | `RangeError('INVALID_CUTOFF')` を投げる |
| A10 | TODO側の `dueDate` | 既存の入力契約（有効な暦日文字列か `null`）を維持。TODO側を検証する新APIは作らない |
| A11 | 保存 | ページ内のメモリーのみ。再読込で合成6件に戻る |

### 許可する振る舞い

- `selectTasks(tasks, {status, cutoff})` の既存の `cutoff` 引数（現状は未使用）を有効にする。
- 一覧の絞り込み欄に、期限の指定日を入れる日付入力を1つ加える。入力を空にすれば全件に戻る。
- 不正な指定日を受けたとき、画面で日本語の案内を出す（後述 UI-4）。

### 除外する振る舞い

- 期限順の並べ替え、範囲（開始〜終了）指定、「今日」「今週」などの自動基準日、相対日付
- 期限超過の強調表示、通知、リマインダー
- サーバー、認証、共有、課金、永続保存（localStorage を含む）
- TODO側 `dueDate` の検証API、`seed.json` の変更、編集・削除機能
- 依存パッケージの追加、ビルド工程の追加、URLへの絞り込み状態の保存

## 2. Tech Stack

- Node.js 24 の組み込み `node:test` / `node:assert/strict`（依存なし）
- ブラウザーのES modules（`app.mjs`）、素のHTML/CSS、既存のCSP（`script-src 'self'` ほか）を維持
- `package.json` は `"type": "module"`、依存なし

## 3. Commands（既存のもののみ）

`lab/` で実行する。いずれも `package.json` に既にある。

```
Test:   npm test            # = node --test tasks.test.mjs
Check:  npm run check       # = node --check tasks.mjs && node --check app.mjs
```

- Lint/format の仕組みは存在しない。追加しない（`npm run check` は構文確認のみ）。
- ブラウザー確認用の開発サーバーコマンドは存在しない。`app.mjs` は `fetch('seed.json')` を使うため `file://` では動かない。静的配信の方法は親が実行時に選び、使ったコマンドを記録する（「未確認の確認事項」U1）。

## 4. Project Structure

```
lab/
  SPEC.md          → この仕様（本書）
  tasks.mjs        → 純粋関数。selectTasks / addTask / toggleTask。期限の絞り込みと検証もここ
  tasks.test.mjs   → node:test の単体テスト。新しいテストもここへ追加
  app.mjs          → 画面の配線（DOM、イベント、描画）。判定ロジックは持たない
  index.html       → 画面の骨組み。絞り込み欄に日付入力を加える
  style.css        → 既存トークン。新しい色やトークンは原則追加しない
  seed.json        → 合成6件。変更しない
  package.json     → 変更しない
```

変更が見込まれるのは `tasks.mjs`、`tasks.test.mjs`、`app.mjs`、`index.html` の4つ。`style.css` は既存の `.filters` のレイアウトで足りなければ最小限だけ触る。

## 5. Code Style

既存の `tasks.mjs` の書き方に合わせる（下は既存コードそのまま）。

```js
export function addTask(tasks, {id, title, dueDate = null}) {
  const trimmed = title.trim();
  if (!trimmed || trimmed.length > 80) throw new RangeError('INVALID_TITLE');
  if (tasks.some(task => task.id === id)) throw new RangeError('DUPLICATE_ID');
  return [...tasks, {id, title: trimmed, dueDate, done: false}];
}
```

- 2スペース字下げ、シングルクォート、セミコロンあり、アロー関数。
- 入力は変更せず、新しい配列を返す（`filter` / `map` / スプレッド）。
- 不正入力は `RangeError` に大文字スネークのコード（`INVALID_CUTOFF`）を載せる。メッセージに日本語文は入れず、画面側で日本語へ置き換える。
- 暦日は文字列のまま扱う。`new Date('YYYY-MM-DD')` を現地時刻へ変換して比較しない。4桁年でゼロ埋めされた `YYYY-MM-DD` は文字列比較で時系列順になるため、比較は文字列で足りる。
- 画面への文字は `textContent` で入れる（既存どおり。`innerHTML` を使わない）。
- テスト名は日本語で、期待する振る舞いを文で書く（既存の `'未完了を選ぶと既存の並び順で4件が返る'` に合わせる）。

## 6. Testing Strategy

- フレームワーク: `node:test` + `node:assert/strict`。場所は `tasks.test.mjs` のみ。
- 単体テスト（`selectTasks` の純粋関数）で受入条件 F・V・R を確認する。新しい振る舞いのテストは、実装前に実行して失敗（RED）を確認し、実装後に成功（GREEN）を確認する。
- 画面（UI-1〜UI-5）は自動テストを足さず、親がブラウザーで実際に操作して確認する。
- カバレッジの数値目標は置かない。代わりに下の受入条件をすべてテストか実操作で確認する。
- 既存の3テストは削除・弱体化しない。

## 7. Boundaries

- **Always**
  - 実装より先に失敗するテストを書き、実際に失敗を見てから実装する
  - コミット前に `npm test` と `npm run check` を実行し、両方成功させる
  - 既存の追加・完了切替・状態の絞り込み・表示・並びを保つ
  - 不正な `cutoff` を検証する（年範囲と実在日）
- **Ask first（この制作では制作担当の事前決定で扱う）**
  - 人の段階承認は行わない。ユーザーは可逆な設計判断と順次掲載を承認済みで、段階ごとの確認を求めないよう指示している。
  - 例外として、新たな支出・外部アカウント・秘密情報が必要になった場合だけ、その点を明示して止める。この作例では発生しない見込み。
  - 依存の追加、`package.json`・`seed.json` の変更、仕様外の機能追加は「確認」ではなく **行わない**。必要になったら本書を先に更新し、理由を残す。
- **Never**
  - APIキー・秘密情報をコミットする
  - サーバー、認証、通知、課金、共有、永続保存を追加する
  - 失敗するテストを消す・飛ばす、期待値を実装に合わせて書き換える
  - `lab/` 外（スタジオのroot、`scripts/`、`skills/`、upstream）を変更する
  - 実行していないコマンドの結果を「成功」と書く

## 8. Success Criteria（受入条件）

代表データは `seed.json` の6件（id: proposal 10-14 未完了 / sample 10-15 未完了 / publish 10-16 未完了 / idea 期限なし 未完了 / brief 10-15 完了 / memo 10-08 完了、年はすべて2026）。

### F: 絞り込み

| # | 入力 | 期待するid（この順） |
|---|---|---|
| F1 | status `open`, cutoff `2026-10-15` | `proposal`, `sample` |
| F2 | status `all`, cutoff `2026-10-15` | `proposal`, `sample`, `brief`, `memo` |
| F3 | status `done`, cutoff `2026-10-15` | `brief`, `memo` |
| F4 | status `all`, cutoff `null` | 6件すべて（入力順） |
| F5 | status `all`, cutoff `''` | 6件すべて |
| F6 | status `all`, cutoff 省略 | 6件すべて（既存呼び出しと同じ） |
| F7 | status `all`, cutoff `2026-10-14` | `proposal`, `memo`（当日を含む） |
| F8 | status `all`, cutoff `2026-10-07` | 空配列 |
| F9 | status `all`, cutoff `9999-12-31` | 期限なしの `idea` を除く5件 |

- F10: どの場合も引数の配列と要素を変更せず、新しい配列を返す（呼び出し後も `seed` は6件・内容同一）。

### V: 不正な指定日（すべて `RangeError`、message `INVALID_CUTOFF`）

| # | cutoff | 理由 |
|---|---|---|
| V1 | `2026-02-30` | 実在しない日 |
| V2 | `2026-02-29` | 閏年でない |
| V3 | `1900-02-29` | 100で割り切れ400で割り切れない年 |
| V4 | `2026-13-01`, `2026-00-10`, `2026-04-31` | 月・日の範囲外 |
| V5 | `0999-12-31`, `10000-01-01` | 年の範囲外 |
| V6 | `2026-1-5`, `2026/10/15`, ` 2026-10-15`, `2026-10-15T00:00` | 形式違い（前後の空白も受け付けない） |
| V7 | `20261015`（数値）, `{}` | 文字列・`null` 以外 |

- 受け付ける境界: `2024-02-29`, `2000-02-29`, `1000-01-01`, `9999-12-31` は例外を投げない。
- V8: 判定結果が実行環境のタイムゾーンに左右されない（`Date` の現地時刻変換に依存しない）。

### R: 既存操作の維持

- R1: 既存の3テストが無変更で通る。
- R2: `addTask` の名前trim、空白のみ・80文字超の拒否、重複idの拒否、`toggleTask` の挙動は変わらない。
- R3: 状態の絞り込みだけ（cutoffなし）の結果は変更前と同じ。

### UI: 画面（ブラウザーでの実操作で確認）

- UI-1: 絞り込み欄に「期限（この日まで）」のラベル付き日付入力がある。`min="1000-01-01" max="9999-12-31"`。初期値は空で、初期表示は6件。
- UI-2: 状態「未完了」＋期限 `2026-10-15` で2件（企画を見直す、作例を確認する）が表示され、件数表示が `2件 / 全6件`。
- UI-3: 日付入力を空にすると、選択中の状態の絞り込みだけに戻る（「すべて」なら6件）。
- UI-4: 不正な指定日を受けたときは画面が止まらず、絞り込み欄の近くに「期限の日付は1000〜9999年の実在する日を入れてください。」を表示し、期限の絞り込みを外した状態（状態の絞り込みのみ）で一覧を出す。有効な日付か空に直すと案内は消える。
- UI-5: 期限の絞り込み中でも完了切替・追加ができ、絞り込みは維持される。期限なしで追加したTODOは、絞り込み中は一覧に出ず全件数だけ増える。0件のときは既存の「該当するTODOはありません。」が出る。
- UI-6: キーボードだけで日付入力に到達・入力・消去でき、フォーカス表示が見える。幅480px以下でも絞り込み欄が横にはみ出さない。
- UI-7: CSPを含む `index.html` の既存の `<head>` 設定を変えず、コンソールにエラーが出ない。

### 完成の基準（Definition of Done をこの作例に合わせたもの）

- 上の受入条件をすべてテストまたは実操作で確認し、その実結果（出力やスクリーンショット）が残っている。
- 新しい振る舞いのテストは、実装前に失敗し実装後に成功したことを実際に見ている。
- `npm test` と `npm run check` が成功。デバッグ出力・コメントアウトした残骸・仕様外の変更がない。
- 外部入力は日付文字列だけで、検証され、表示は `textContent`。
- ロールバックは `lab/` のgitで該当コミットを戻せば足りる。静的ページのためログ・計測は追加しない。
- 人によるレビュー・承認は行っていない。代わりに親がテスト実行・ブラウザー確認・コードレビューを行い、その実結果だけを記事に使う。

## 9. 未確認の確認事項（Open Questions）

人の判断を待つ問いはない。以下は親が実行して確かめる項目。

- U1: ブラウザー確認の静的配信の方法（既存コマンドがないため）。使ったコマンドを記録する。
- U2: 実際のブラウザーで、日付入力に年 `0999` などの範囲外を手入力したとき `value` に何が入るか。`''` になるなら UI-4 は画面からは起こらず、単体テストの V のみで担保される。そのことを記事で正直に書く。
- U3: `npm test` を異なるタイムゾーン（例: PowerShell で `$env:TZ='Pacific/Kiritimati'; npm test` と `$env:TZ='America/Los_Angeles'; npm test`）で実行し、結果が同じか（V8）。Windows上のNode 24で `TZ` が効くかも含めて確かめる。
- U4: 既存の `selectTasks` は `all`/`done` 以外の status を「未完了」として扱う。この挙動は今回の範囲外として変えない。レビューで指摘が出ても別件として記録する。
- U5: 既存の `addTask` は `dueDate` を検証しない（A10 のとおり維持）。不正な `dueDate` を持つTODOがあった場合の絞り込み結果は未定義のままとする。
