# 作例用の依頼

「小さなTODOアプリへ期限の絞り込みを追加して。まず仕様と完成条件を整理し、実装後に境界値と既存操作も確認してほしい。」

架空の工房と合成TODO6件、既存コードを制作担当が作例用に用意した。実在の顧客やProductionのTODOではない。ユーザーは制作の内部判断と順次掲載を承認済みで、工程ごとの確認を繰り返さないよう指示している。これはユーザーが各仕様を対話で承認したという実績ではない。

## 制作担当の事前の決め方

- 追加機能は「期限が指定日まで」の絞り込み1つ。日付はYYYY-MM-DDの暦日で、当日を含む。指定日なしなら従来の全件へ戻る。
- 期限なしは、期限の絞り込み中だけ除外する。状態（すべて/未完了/完了）の絞り込みと同時に効く。並びは入力順。
- Dateとして現地時刻へ変換して日付をずらさない。基準は自動の今日ではなく、入力した暦日。この作例の代表は2026-10-15。年1000〜9999の実在Gregorian日だけを受け付ける。
- 不正なcutoff（2026-02-30等）はRangeError('INVALID_CUTOFF')。空文字/nullは絞り込みなし。taskのdueDateは有効な暦日文字列かnullという既存入力契約を維持し、不正taskスキーマの新APIは作らない。
- 既存の追加（名前trim、空白/80文字超拒否）、完了切替、状態絞り込み、名前表示、順番を保つ。入力を変更せず新配列を返す。
- 保存はこのページ内のメモリーだけ。再読込で合成6件に戻る。サーバー/認証/通知/課金/共有/永続保存は追加しない。
- シンプルな既存UI・無依存のNode24/node:testとブラウザーESmodulesを維持。依存導入、既存root作業、workspace内専門repoの変更はしない。

## 進め方

最初のOpus実行は仕様だけ（Objective/Commands/Structure/Style/Tests/Boundariesの6領域、受入と未確認）。親が確認してから別のモデル呼び出しで計画/テストへ。人の段階承認は実施していないと明記する。

1段目は期限の絞り込みをテストで実RED→最小実装+UI→実GREEN/ブラウザー動作→commit。2段目は不正な暦日のテストで実RED→入力検証→実GREEN→commit。その後に境界/回帰とコードレビューの実条件反転を行う。画面と動画の紹介は確認した実結果から作る。

代表入力: status open/cutoff2026-10-15→proposal,sample。status all/cutoff2026-10-15→proposal,sample,brief,memo。解除statusall/cutoffnull→6件。
