    呼び出し方と3つの設定
    
      
    
        
    
          
    このページ：ブラウザーで full版
    

    new Defuddle(
  new DOMParser().parseFromString(sample.input, 'text/html'),
  { url: sample.url, markdown: true, useAsync: false, removeImages: true }
).parse()
    
          
    full版の parse() は、本体の parse() で本文と題名・著者を取り出し、続けて toMarkdown で content をMarkdownにします。読み込みのたびに3件を1回ずつ実行し、保存済みの出力と全文を照らし合わせます。
    
        
    
        
    
          
    元の制作：Node.js と jsdom
    

    await Defuddle(jsdomDocument, url, options)
    
          
    Node版は内部で parseAsync() を呼び、useAsync: false の分岐で手元の結果を返してから、Markdownに変換します。その実出力が extraction-results.json です。このページではNodeを実行し直していません。
    
        
    
      
    
      
    
        
    markdown: true
    content をMarkdownで返します（full版に入っている変換）。
    
        
    useAsync: false
    手元のHTMLで本文が取れないときに外部のAPIで補う機能を使いません。この3件では、その補完の分岐を通っていません。
    
        
    removeImages: true
    画像を除く設定です。3つの入力に画像がないため、この作例では効果を示していません。
    
        
    url
    example.test のURLはページの文脈として渡すだけで、取得しません。任意のURLやファイルは入力できません。

        試した範囲と、していないこと
        
            
          
          • Defuddle は JavaScript のライブラリ（と CLI）です。SKILL.md・モデル・要約AIではありません。このページはAIやAPIに接続しません。
            • 
          
          • 3つのページは作例のために書いた架空の記事です。保存手順は実在のアプリの保存を実行したものではなく、検索画面のテストは実際の調査や効果の測定ではありません。原文の「残る2人は、旧画面のほうが慣れていて速いと答えています」「実務での効果は未検証です」も content にそのまま残っています。
            • 
          
          • 図の部屋の中の「選ぶ・外す」は原典の説明にもとづく説明図です。内部の削除ログ、選ばれた要素、処理の順序や時間を計測したものではありません。ヘッダーやフッターがいつも除かれるとも限りません。
            • 
          
          • 試していないこと：HTMLでの出力、CLI、数式・脚注の変換、画像のある入力、外部APIでの補完、任意のWebページでの品質。この3件で取り出せても、どのページでも同じとは限りません（原典の README にも開発中とあります）。
            • 
          
          • 元の制作の画面・28秒の映像・Nodeでの実行・バンドルのビルドは、この図の改修でやり直していません。図と映像の新しいコードは claude-opus-5-5 が書いたもので、動作や見た目の確認、人の承認はこのファイルの作成時点では行っていません。
