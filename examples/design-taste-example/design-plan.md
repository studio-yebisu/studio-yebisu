# デザイン計画：余白図書室（架空）十一月の催し

> この文書は、実装の前に書いたデザイン計画の写しです。公開用に、フォルダの書き方だけを作例のフォルダからの相対パスに直しました。実装で計画と変えた点は、README.md の「計画から変えた点」に書いています。

**design read**：近所の親子・おとな・来館者向けに、架空図書室の催しを「探す→日時を読む→参加方法を開く」ための一覧ページとして読む。japanese-minimalで、紙と墨、罫線の目録、明朝とゴシック、印の赤は二か所だけ。静かだが、操作は最初の画面に出す。

読んだ原典：`vendor/design-taste/` の README・LICENSE（MIT, Copyright (c) 2026 Mustafa）、`skills/` 配下の design-taste / japanese-minimal / taste-accessibility / taste-typography / taste-ux-copy。依頼文にあった `vendor/skills/…` には実体がなく、`vendor/design-taste/skills/…` を読んだ。

## 1. 対象と目的

- 利用者：近所の親子、おとな、年齢を問わない来館者。急がないが、操作を探したくない人。
- 目的：6件から条件で絞り、日時・対象・会場・参加方法をその場で読む。申込・予約・ログイン・保存はしない。
- 主役は動く一覧。解説・作り方・依頼文は一覧の下に置き、最初の画面を運用ログやQAメニューにしない。

## 2. ジャンルと構成

- ジャンルは japanese-minimal の一つだけ。ほかのパックは混ぜない。
- 非対称の構成（1024px以上）：12列グリッド。左3列に縦書きと絞り込み、右8列（1列空け）に一覧。各行は「日付の列（固定幅）｜題名・対象・会場・説明・参加方法」の二段。中央揃えの見出しやカード三つ並びは使わない。
- 縦書き（一か所だけ）：見出し横の「二〇二六年 十一月」を `writing-mode: vertical-rl` で置く。月の情報は見出しと各日付にもあるため、縦書きは `aria-hidden="true"` にして読み上げの重複を避ける。320pxでも3字幅程度に収め、操作を押し出さない。
- 印（二か所だけ）：ワードマーク横の「余」と、フッターの「余」。赤#B3392Aの角形（角丸2px以下）、白い字。装飾なので `aria-hidden="true"`。
- 余白：行間と罫線で間をとる。ただし原典の「hero ≥20vh」は採らず、ヘッダーを詰めて、1280×720でも320pxでも検索欄が最初の画面に入るようにする。一覧と解説の間は広い画面で160px、狭い画面で96px。
- 見出し構成：h1「十一月の催し」→ h2「催しをさがす」（操作）→ h2「催しの一覧」→ 各催しは h3 → h2「この作例について」→ h3（素材／適用と調整／確認範囲／依頼文で試す）。見出しレベルは飛ばさない。
- ランドマーク：先頭にスキップリンク「一覧へ移動」（フォーカス時に表示、`#main` へ）、`header`、`main id="main"`、名前付き `section`、`footer`。

## 3. 文字

- 書体はOSの明朝とゴシックだけ。Webフォントは読み込まない。
  - 明朝：`"Hiragino Mincho ProN", "Yu Mincho", "YuMincho", "BIZ UDPMincho", serif`
  - ゴシック：`"Hiragino Sans", "Hiragino Kaku Gothic ProN", "BIZ UDPGothic", "Meiryo", sans-serif`
- 階層（すべてrem、`clamp()` にremの下限を入れる）
  - h1：明朝400、`clamp(2rem, 6vw, 3.5rem)`、行送り1.25。
  - 日付「11月7日」：明朝、1.5rem。曜日と時刻はゴシック16px。日付が目で追う索引になる。
  - h3（催し名）：明朝、1.25rem、行送り1.5。
  - 本文：ゴシック16px、行送り1.8、1行40字前後（`max-width: 38em`）。
  - ラベル（対象・会場・件数）：ゴシック14px、字間0.08em、濃い灰。
- 太さは400と600の2つまで。斜体と擬似太字は使わない。

## 4. 色とコントラスト

| 役割 | 色 | 背景#F4F1EAとの比（計算上の目安） |
|---|---|---|
| 紙 | #F4F1EA（面は #ECE8DF） | — |
| 墨（本文・見出し・フォーカス枠） | #33302B | 約11.6:1 |
| 濃い灰（ラベル・補足の文字） | #625C53 | 約5.9:1（#ECE8DF上で約5.4:1） |
| 薄い灰（装飾の罫線だけ） | #8A8378 | 約3.3:1。文字には使わない |
| 印の赤（印・本文リンクの下線） | #B3392A | 約5.3:1。印の白字は約5.9:1 |

- 入力欄とselectの枠は#625C53（UI部品の3:1以上）。フォーカスは墨の2px outline、offset 2px。
- 赤は印・リンクだけに使う。日付、選択中の状態、フォーカスには使わない。一画面あたり4回以内。
- 純白・グラデーション・影・赤の面は使わない。
- 比はいずれも計算した見込みの値。実装後に実際の色で測り直す。

## 5. 機能UI

- 操作：`<form role="search" aria-labelledby>` の中に以下を置き、フォームの送信はしない（Enterで画面遷移しない）。
  - `<label for="q">名前・説明・会場から探す</label>` ＋ `<input type="search" id="q">`
  - `<label for="aud">対象</label>` ＋ ネイティブ `<select id="aud">`（すべて／子ども／おとな／どなたでも。値は all / children / adults / everyone）
  - `<button type="button">条件を解除</button>`
  - ラベルは欄の上に常に見える位置に置き、placeholderだけで済ませない。
- 件数：`<p role="status">6件中6件を表示</p>`。入力のたびに更新する。
- 各催し（`ol` の `li`）：`<time datetime="2026-11-07T10:30">11月7日（土）10:30〜11:00</time>`、題名、対象、会場、説明、参加方法の要約（例「申込不要」）を、閉じた状態でも全件に表示する。曜日は日付から計算する（土・金・土・土・日・土）。
- 参加方法：ネイティブの `<details><summary>参加方法：申込不要</summary>` で開閉し、中に registration の本文をそのまま入れる。外部リンク、申込ボタン、フォームは置かない。summaryは高さ44px以上。
- 架空であることの明示：h1の直下に「余白図書室は架空の図書室です。催しは作例用の合成データで、実際の参加・申込はできません。」と書く。参加方法の本文も、データにある架空の注記をそのまま使う。
- データ（名前・日時・分類・会場・本文・参加方法）は変えない。

## 6. 絞り込みの決まり

- 正規化：`norm = s => s.normalize("NFKC").trim().toLowerCase()`。検索語と各項目の両方に同じ処理をかける。
- 検索範囲：題名・説明・会場だけ。項目ごとに `includes` で判定する（項目をつなげて、境目をまたいで一致させない）。空の検索語はすべて一致とする。
- 対象：`all` 以外は `audience` と完全に一致するものだけ。
- 検索と対象はANDで組み合わせる。
- 並び順：読み込み時に `date + start` で一度並べ、その後は `filter` だけを使うので順序は変わらない。
- 表示：検索語の表示はすべて `textContent` で行い、HTMLとして解釈しない。
- 保存しない：localStorage・cookie・送信は使わない。操作でURLも書き換えない。
- 0件のとき：「条件に合う催しはありません」＋理由（「『{検索語}』を含む{対象}の催しは、十一月の一覧にありません」）＋「条件を解除して6件を表示」ボタン。解除したら、フォーカスを「催しの一覧」見出し（`tabindex="-1"`）へ移す。

### サンプルの合図と期待する結果（一覧の画面と一致させる）

| 合図 | 操作上の状態 | 結果 |
|---|---|---|
| `#all` | 対象「すべて」・検索空 | 6件（e01〜e06、日付順） |
| `#children` | 対象「子ども」・検索空 | e01, e04 |
| `#reading` | 対象「すべて」・検索「短編」 | e02 |

- 読み込み時と `hashchange` のときだけ、合図を検索欄とselectの値に反映する。知らない合図は無視して6件を表示する。合図と同じ名前の要素idは作らない。
- 実装後に確かめる例：存在しない語→0件。全角空白つきの「　短編　」→e02。「子ども」＋「短編」→0件（AND）。全角の「ＡＢＣ」は半角の「abc」と同じに扱う。`<img src=x>` は文字として表示され、0件になる。

## 7. 320pxでの並び

ワードマーク＋印 → h1と縦書き → 架空の注記（2行以内） → 検索・対象・解除（縦に並べ、各44px以上） → 件数 → 一覧 → 解説 → フッター（印）。
各行は日付と時刻を最上段に置き、題名、対象・会場、説明、参加方法の要約の順に1列で並べる。横スクロールなし、文字の切れなし。ページの案内文など長い説明は、すべて一覧の下へ置く。

## 8. 原典の適用と、文脈による調整

**そのまま適用したもの**
- design read を先に宣言する。
- never list：グラデーション、中央ヒーロー、カード三つ並び、絵文字、影、`rounded-2xl` を使わない。
- 紙・墨・印の赤。箱ではなく罫線。番号のない目録行。印は二か所、縦書きは一か所。
- 角丸2px以下。斜体なし。感嘆符や最上級の言い方を使わない。
- 0件表示は「何が・なぜ・次の操作」の三点。ボタンは動詞で書く。
- 自作の部品ではなくネイティブの select と details を使う。
- h1は一つ。ラベルは欄と結びつける。スキップリンクを置く。

**意図して調整したもの**
- 灰#8A8378の文字 → #625C53。#8A8378は罫線だけに使う（文字にすると4.5:1に届かない）。
- ラベル10–11px・字間0.18em・大文字 → 14px・字間0.08em。日本語の読みやすさを優先した。
- Shippori Mincho・Zen Kaku Gothic → OSの書体（依頼の条件）。
- 等幅のラベル → 使わない（書体は二種類までにする）。
- hero ≥20vh・セクション間160px → 操作を最初の画面に入れるため、ヘッダーは詰める。160pxは広い画面の一覧と解説の間だけで使う。
- design-taste の大きな見出し（3–7rem）・CTAの考え方 → この作例は道具としての一覧なので使わない。CTAも置かない。
- 各セクションのフェード → 使わない。絞り込みで一覧が動くと読みにくい。動きはhover時の色変化200msだけにし、`prefers-reduced-motion` では0にする。
- 本文の行送り1.55–1.7 → 日本語の本文なので1.8。1行の長さは45–75字ではなく、40字前後。

## 9. 確認の計画

- design preflight：design-taste §7 と japanese-minimal §6 の各項目を、画面を見て一つずつ確かめる。当てはまる項目があればその部分を作り直す。
- キーボード：スキップリンク→検索→対象→解除→各summary（Enter/Spaceで開閉）→0件時の解除ボタン、の順にフォーカスが見え、操作でき、どこにも閉じ込められないこと。
- コントラスト：§4の組み合わせを実際の色で測り直す。入力欄の枠とフォーカス枠も測る。
- レスポンシブ：320 / 375 / 768 / 1280px。1280pxで200%に拡大しても横スクロールや文字の切れがないこと。
- 動きを減らす設定：`prefers-reduced-motion` で遷移が0になること。
- 絞り込み：§6の表と例を、実際の画面で確かめる。
- **保留**：スクリーンリーダー（NVDA / VoiceOver）での読み上げと、人による承認。どちらもこの環境ではできないので、「未実施」と書き、合格とは書かない。スクリーンショットや自動テストが通っても、アクセシビリティ全体の適合を示すものではない。

## 10. 文章で約束しないこと

品質、速さ、転換率などの測定値は書かない。実在の図書館が使えるとも書かない。下の「依頼文で試す」は、AIをその場で実行するものではない。依頼文の本文と、§6の合図リンクで一覧の状態を再現するだけで、作例の見本とAIの実行は分けて書く。動画は別の工程で作り、この計画には含めない。実装の範囲も、この計画に書いたものから増やさない。
