          Markdownは選んでいる発見1件分（引用・行ID・反する発言・人数・次の一歩）、JSONは保存済みの整理全体（outputs/synthesis.json と同じ内容）です。

          3原文のメモ

          制作担当がこの作例のために書いた架空のメモです。すべて架空の参加者の自己申告で、操作を観察した記録ではありません。行IDは整理の引用と同じです。

          P01月に数回借りる、個人の利用者

          スマホで移動中に空き時間を探す。発言は自己申告。

          1. P01-L01予約ボタンを押したあと、終わったのか分からなくて、同じ予約をもう一度送ったことがあります。
          2. P01-L02空いている日を探すときは、日付を一日ずつ開いて確かめています。
          3. P01-L03予約の控えはメールに残したいです。SMSはほかの連絡に埋もれます。
          4. P01-L04道具の写真が大きいので、何を借りるかは決めやすいです。
          5. P01-L05受け取り時間を変更できるのか、予約を送る前に知りたいです。
          P02週に数回借りる、小さな制作チームの担当者

          チームの予定と照合し、スマホからまとめて予約する。発言は自己申告。

          1. P02-L01完了画面を閉じてから、予約番号をチームに伝えるために、最初から一覧を開き直しています。
          2. P02-L02前日の取消料がかかることに、予約したあとで気づきました。送る前に条件を見たいです。
          3. P02-L03当日の変更はSMSで知りたいです。メールは作業が終わるまで見ない日があります。
          4. P02-L04いつも同じ曜日に借りるので、日付を一つずつ開く今の方法でも困っていません。
          5. P02-L05前に借りた道具の名前が一覧に残るので、次の予約で探し直さずに済みます。
          P03初めて利用する、個人の利用者

          週末の道具を探してスマホで予約を試す。発言は自己申告。

          1. P03-L01送信した直後に完了の文字が見つからず、予約できたか確認するメールをお店に送りました。
          2. P03-L02使いたい週末が空いているか、月の予定をまとめて見たいです。
          3. P03-L03取消できる期限が分からなくて、その場では予約せずに閉じました。
          4. P03-L04写真で道具の大きさが分かるのは助かりました。
          5. P03-L05SMSかメールかは、まだ選んだことがなく、どちらがよいか分かりません。
