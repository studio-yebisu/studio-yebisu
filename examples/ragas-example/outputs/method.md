# 評価の方法：凪の図書室FAQ × Ragasの文字列指標

この作例は、架空の図書室FAQの同じ10問について、変更前（before）と変更後（after）の固定回答を、Ragas の文字列指標3つで採点し、結果を根拠資料と制作担当の照合メモと並べて読むためのものです。採点は `evaluate.py` が行い、結果は `outputs/evaluation.json` に保存します。閲覧ページ（`index.html`）は保存した結果を読むだけで、Ragas も AI も動かしません。

## 使ったAPI

原典は vibrantlabsai/ragas の固定コミット `298b68274234c060deacab3cf5fb52aa3a20e885` です。インストール済みの未改変ソースから、次の3クラスを `ragas.metrics.collections` から読み込み、`await metric.ascore(reference=..., response=...)` を呼んで、戻り値の `MetricResult.value`（float）を使います。実装はどれも `src/ragas/metrics/collections/_string.py` にあり、同梱の `vendor/ragas/` で読めます。

| id | 表示名 | Ragas のクラス | 実装が返す値 |
| --- | --- | --- | --- |
| `exact_match` | 完全一致 | `ExactMatch()` | `float(reference == response)`。1文字でも違えば0.0 |
| `string_similarity` | 文字列の近さ | `NonLLMStringSimilarity(distance_measure=DistanceMeasure.LEVENSHTEIN)` | `1 - rapidfuzz.distance.Levenshtein.normalized_distance(reference, response)` |
| `string_presence` | 基準文の包含 | `StringPresence()` | `float(reference in response)`。参照文の全体が回答に含まれれば1.0 |

3つとも LLM・埋め込み・APIキー・アカウント・外部サービスを使いません（`base.py` は `llm`・`embeddings` 属性を持つ指標だけを検査し、この3クラスはどちらも持ちません）。指標の説明は同梱の `docs/concepts/metrics/available_metrics/traditional.md` にあります。

## 入力

`input/faq-pairs.json`（形式 `studio-yebisu-faq-fixture-v1`、`fictional: true`）は、この作例のために書いた架空の入力です。

- 資料10件（D01〜D10）：「凪の図書室」の決まりを1文ずつ書いたもの。
- 問い10件（Q01〜Q10）：それぞれ1件の資料を根拠にし、参照文（`reference`）はその資料の本文と完全に同じ文字列です。
- 固定回答20件：各問に before と after の2件。意図して、誤り・言い換え・根拠にない追記を混ぜています。before/after は入力の名前で、実際のRAGシステム・モデル・検索器を変更して動かした履歴ではありません。
- 照合メモ：各回答に、制作担当が入力時に書いたラベル（`grounded` この固定資料と合う／`contradiction` この固定資料と矛盾／`unsupported_addition` この固定資料に根拠のない追記）とメモがあります。Ragas の出力でも LLM judge の出力でもなく、人による承認でもありません。

## 計算

1. 入力を検証します。形式、`fictional: true`、資料と問いがそれぞれ10件でIDが重複しないこと、各問の根拠資料IDがちょうど1件の既知IDであること、参照文がその資料の本文と完全に一致すること、before/after の回答とラベル（3種類のどれか）とメモがあること。外れたら何も書かずに止まります。
2. 10問 × 2回答 × 3指標 = 60回、`ascore` を順に呼びます。文字列はUnicodeのまま渡し、正規化・空白除去・表記ゆれの吸収はしません（NFKC正規化は閲覧ページの検索だけに使います）。
3. 返った値が有限の数で0〜1に収まること、完全一致と包含は0.0か1.0であることを確かめます。外れたら止まります。成功した呼び出しを数え、60回でなければ止まります。
4. 各回答の値を丸めずに `rows[].before.scores`・`rows[].after.scores` に入れ、入力の項目はそのまま残します。
5. `summary` に、before/after ごとの10問の平均（`math.fsum` の合計を10で割った値）と、完全一致・包含が1.0だった件数を書きます。照合メモのラベル数は `annotation_counts` に別に書き、入力の値であることを明記します。

閲覧ページは平均・各値を小数第3位まで表示します。保存した値は丸めていません。

## 点数が示すこと・示さないこと

3指標が比べるのは、参照文と回答の文字です。回答が根拠に忠実か、事実として正しいか、意味が同じかは判定しません。

- 完全一致は、正しい言い換えも0.0にします。完全一致の件数や平均は正答率ではありません。
- 文字列の近さは、期限や数字のような1文字の違いでも高い値のままです。
- 基準文の包含は、参照文のあとに根拠のない文が足されても1.0のままです。

採用や合否を決める基準値は置いていません。10問の架空データで、代表的なベンチマークではありません。Ragas の LLM を使う指標（faithfulness・factual correctness など）、検索の評価、モデルの比較は行っていません。

## 読みどころ（入力から見込まれる対比）

次は入力の文字列と照合メモから見込んだ対比で、実行結果ではありません。実際の値は `outputs/evaluation.json` で確かめます。

- 完全一致の件数：before で4件（Q05〜Q08）、after で7件（Q01〜Q04・Q06・Q09・Q10）の見込みです。件数が増えても、after には照合メモで要確認の回答が2件あります。
- Q07：after は「18時」を「19時」に変えた回答です。1文字の置換なので文字列の近さは高いまま、完全一致は0.0になる見込みです。期限が変わっていることを示すのは照合メモ（contradiction）です。
- Q08：after は参照文のあとに「延滞しても連絡は不要です。」を足した回答です。参照文の全体を含むため基準文の包含は1.0の見込みですが、照合メモは根拠にない追記（unsupported_addition）としています。
- Q05：after は意味を保った言い換えで、完全一致は0.0の見込みです。内容が根拠と合うことは、点数ではなく照合メモ（grounded）だけが示しています。Q09 の before も同じ種類の言い換えです。

## 実行のしかた

- `RAGAS_DO_NOT_TRACK=true` を、Ragas を読み込む前に設定します（`_analytics.py` は最初に読んだ値をキャッシュします）。実行後、Ragas 自身の `do_not_track()` が True を返すことを確かめて `runtime.tracking_disabled` に記録します。
- Ragas の読み込みと採点のあいだ、Python の `socket.socket.connect`・`connect_ex`・`socket.create_connection` と、実行中のイベントループの `create_connection`・`sock_connect` を差し替えて接続を拒否し、関数名と接続先のホスト・ポートだけを記録します。1件でも試みがあれば、結果を書かずに失敗します。DNS問い合わせや、C拡張が独自に開く接続はこの記録の対象外です。
- 拒否はイベントループの作成後に始めます。Windows ではイベントループが内部の通知用に localhost への接続を作るためです。
- 指標の計算・Ragas のクラス・読み込みは差し替えていません。Ragas を読み込めないときは、自作の計算で代わりに埋めずに失敗します。
- 出力先が既にあれば上書きせずに止まります。時刻や乱数は使わないため、同じ入力と同じ環境なら同じ内容になります。
- 出力には、入力の相対パスとSHA-256、原典のリポジトリとコミット、Python・Ragas・rapidfuzz の版、呼び出し回数を書きます。手元の絶対パス・環境変数・認証情報は書きません。

Ragas の版は、Git情報のないソースZIPから入れるため `SETUPTOOLS_SCM_PRETEND_VERSION_FOR_RAGAS=0.0.0+studio.298b68274234` で付けた手元の版名になります。Ragas の正式なリリース番号ではなく、原典は `source.commit` で特定します。

## 閲覧ページでの扱い

- `input/faq-pairs.json` と `outputs/evaluation.json` を取得し、HTTPの状態、形式、20件の回答とメモが入力と同じこと、3指標の値がそろっていること、10問のIDが一致すること、集計が各問の値と合うことを確かめてから表示します。内蔵の代わりのデータはありません。
- WebCrypto が使えるときは、取得した入力ファイルのバイト列からSHA-256を計算し、結果の `input_sha256` と照合します。使えないときは「照合していない」と表示します。
- 「変更後に要確認メモ」「変更後に根拠と一致メモ」の絞り込みは入力の照合メモのラベルによるもので、Ragas の分類ではありません。
- 回答の色付き部分は、参照文と前後の文字が一致しない範囲を示す表示上の目印で、意味の判定ではありません。

## 制作担当の実行追記

固定版をPython3.12.9の私的venvへ入れ、実際のRagas APIを20回答へ計60回呼びました。入出力全文、Unicode文字列距離・完全一致・包含を別実装でも照合し、別出力への再実行は同バイトでした。既存出力の上書き拒否と、重複IDの不正入力から出力を作らず失敗することも確認済みです。完全一致の件数4/10→7/10、文字列の近さの平均0.7884922267275208→0.8835109447004609、包含平均0.4→0.8。Q07変更後0.96875、Q08変更後の包含1、Q05変更後の完全一致0を実結果で確認しました。

上の受領時点の「未実行」「見込み」は当時の状態です。この追記とoutputs/evaluation.jsonが実行後の記録です。根拠との照合メモの意味は制作担当が全20回答と10資料を読み直して確かめました。Ragasの自動意味判定や人承認ではありません。ブラウザーと動画の確認は、後続のverification.jsonに記録します。
