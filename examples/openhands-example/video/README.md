# 解説動画の編集ソース（OpenHands 作例・33秒）

設定ファイル → 形式の点検 → 保存ファイル の図を、33秒（30fps・990フレーム）で動かす解説動画のソースです。本編は縦 720×1280（iPhone などのスマホ向け）、別版は横 1280×720。どちらも同じ時刻表で、各サイズの配置を作り直して描きます。

| ファイル | 役割 |
| --- | --- |
| `index.html` | 編集ページ（プレビュー・場面の一覧・素材の照合結果） |
| `video.js` | 映像の本体。`window.seek(t)` が時刻 t の完成した1枚を canvas に描く |
| `video.css` | 編集ページの見た目。書き出しのときは canvas だけを出す |
| `storyboard.json` | 場面・ナレーション・素材のハッシュ・配置・連続性・示さないこと |
| `assets/` | 固定した8つの素材と `manifest.json`（制作側が用意。編集しない） |

## プレビュー

作例のフォルダー（`index.html` と `render.py` のある場所）で、ローカルの HTTP サーバーを開きます。ファイルを直接開くと素材を照合できません。

```text
python -m http.server 8000
```

- 縦：`http://localhost:8000/video/`
- 横：`http://localhost:8000/video/?layout=wide`

開くと、素材8件の照合が終わるまで映像は出ません。照合が終わると最初のフレームが出て、操作が使えるようになります。

- **再生／一時停止**：押したときだけ始まります（自動では再生しません）。照合済みの `narration.wav` が鳴り、映像はその音の時刻に合わせて進みます。音を再生できないブラウザーでは映像だけが進み、その旨を表示します。
- **時刻のスライダー**：動かすと再生が止まり、その時刻の画になります。音は鳴りません。
- **先頭へ**：止めて0秒の画に戻ります。
- **消音**：プレビューの音だけを消します。
- **場面**：押すとその場面の代表の時刻で止まります。
- 映像の下に、その時刻のナレーションの文を表示します（映像の中には文字のカードを出しません）。

## 描く前に確かめること

`window.motionReady` は、次がすべて合ったときだけ成功します。1つでも合わなければ canvas を隠し、操作を止め、理由と「もう一度読み込む」を出します。代わりに埋め込んだ記録はありません。

1. `assets/manifest.json` の SHA-256 が `d6370b8ad33b837a2e47780e9250a3079f43f16f1de950ef4c3bdadf812a7080`。8件の名前・SHA-256・バイト数が `video.js` に固定した値と一致。
2. 8件それぞれの SHA-256 とバイト数が manifest と一致。
3. `automation-runs.json`：形式、OpenHands の固定版（`OpenHands/OpenHands`・`e4775b4ba61a83ba80af5f7b0b826201b8e8ea05`・1.27.1・MIT）、原典12ファイル・`@openhands/extensions` 0.30.0 の29ファイル（`vendor-lock.json` と一致）、O01〜O08 の8件（重複なし）、形式OK 6・止まった 2、確認107件すべて合格。
4. 図の4場面の事実：O03 は時刻（`spec.trigger.schedule`）の欠け1件で止まった。O04 は O03 に時刻だけを足した入力で形式OK、ファイルは `O04.automation.json`・602バイト・SHA-256 `5e1ae14b…5aa3`。O06 は cron の形でない時刻でも形式OK（cron は未確認）。O07 は参照先2件のうち先頭だけがファイルに入った。
5. `automation-settings.json`・`expected.json`（実行前に固定した入力と期待）が記録と一致。
6. `independent-checks.json` の155件と `reproduction-checks.json`（記録と6つのファイルの再現）が、同じ記録の SHA-256 に対して合格。
7. `narration-cues.json`：33秒・30fps・990フレーム・48000Hz、5つの文と時刻・SHA-256、6つの場面が `video.js` に固定した値と一致。
8. `narration.wav`：PCM16・モノラル・48000Hz・ちょうど33秒。5つの区間それぞれに音がある。
9. フォントの準備（`document.fonts`）を待つ。

## 時刻の契約

- `window.motionConfig = { duration: 33, fps: 30, width: 720, height: 1280, posterTime: 12, audioEvents: [] }`。レンダラーが渡す `window.renderConfig` の幅・高さ・fps を使います。
- `window.seek(t)` は時刻 t だけから描きます。前の seek の順番・壁時計・乱数は使いません。同じ t なら、新しいページでも別の順番でも同じ画になります（同じ環境での再現。別の OS やフォントで同じ画になる保証ではありません）。
- `window.__MOTION_RENDER__` が真のときは、プレビューの音とタイマーを使わず、canvas だけを構図の大きさで出します。CSS アニメーションはありません。

## 書き出し

書き出しは作例のフォルダーの `render.py` を使います。同梱の `tools/motion-reel/render.mjs`（Motion Reel のレンダラー・MIT License）をソースの外の使い捨ての写しで動かし、`video/assets/narration.wav` を `--audio` に渡します。レンダラーは音を33秒に揃え、ラウドネスを揃えて AAC にします。出力先は毎回、ソースの外の空のフォルダーにしてください（既存の書き出しは上書きしません）。

```text
python render.py --out <ソースの外の空のフォルダー>/vertical --width 720 --height 1280
python render.py --out <ソースの外の空のフォルダー>/wide --width 1280 --height 720
```

Node.js 20以上・Chrome・FFmpeg と ffprobe が必要です。レンダラーの初回だけ、`tools/motion-reel/` で `npm install --ignore-scripts` を行います。`--stills-only` でフレームの静止画とコンタクトシートだけを出せます。

## 書き出し後の確認

33秒・30fps・990フレームの縦版720×1280と横版1280×720を、実生成した日本語Irodori-TTSナレーション5区間と同じ時刻で書き出しました。代表・連続・スマホ幅・終端の画、別順序と新ページの同時刻PNG一致、全デコード、ブラウザーでのMP4再生終了と編集ソースの実音源再生・シークを確認しました。音声の聴取、人による承認、実機iOS/Safari/VoiceOverは未確認です。

音源は5区間のTTSを編集せず無音の間を空けて配置した33秒PCMです。各cueの原PCMとの一致を確認し、MP4化ではMotion Reelが音量調整・AAC圧縮を行っています。聴取は未確認です。原典API入力と結果は改修前と同じものを引き継いでいます。
