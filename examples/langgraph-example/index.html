LangGraphは何か

LangGraph は、Pythonで「共有する状態（state）」と「それを読んで更新する関数（ノード）」をつなぎ、条件で道を分け、途中で止めて同じ所から続けられるようにするライブラリです。SKILL.md でも、AIモデルでも、自動で承認するエージェントでも、ホスト型のAPIでもありません。

図の流れ

  1. 組む　元の制作AI（Opus 5.5）が、原典のAPIと依頼文を読んで workflow.py を書きました。制作担当が別の工程でPythonを動かし、StateGraph を InMemorySaver 付きで compile して、申請ごとの thread_id で invoke しました。
  2. 止まるまで　架空の申請は1枚の state のカードとして、5つのPython関数をつないだ道を、決まった規則で進みます。各ノードは state を読み、変えた項目だけを返します。validate のあとの分岐は入力の不足・誤りだけで決まり、完全な申請は金額にかかわらず review の interrupt で止まります。止まった state と next=[review] は、同じプロセスのメモリにその申請の thread として残ります。
  3. 再開後　スクリプトが入力ファイルのテスト値を Command(resume=…) で同じグラフ・同じ thread に渡すと、review が先頭からやり直され、interrupt がその値を返します。回答が state に入り、finalize が日本語の要約を書いて終わります。最終 state は保存記録（JSON）になり、元の実データの画面で読めます。
  4. 返却日のない申請　validate が end_date の空欄を見つけて needs_input へ進み、そこで終わります。見積・停止・再開はありません。

AIが書いた範囲　元の Opus 5.5 が workflow.py と元の画面を書きました。制作担当が動かした範囲　Pythonの実行（外への接続を止めた1つのプロセス、トレースなし）。実行時のノード　5つとも決まった規則のPython関数で、5つのAIではありません。グラフはLLMを呼んでいません。

この図は元の実行記録の図解で、新しい実行ではありません。いまのブラウザーは保存したファイルを読むだけで、Python・LangGraph・AIの推論を動かしません。紙・門・トレイ・画面の形は説明用の絵で、カードに出る値はすべて保存したチェックポイントから読んでいます。

6つは選んだAPIを説明するための整理で、原典の共通の形式ではありません。押すと図の該当箇所が光ります。選んだ申請はそのままです。

この作例の範囲

      
    
        
  • 入力は架空　申請者・催し・単価・基準額は作例用です。estimate は数量×単価の合計で、日数は掛けません。合計30,000円以上で予算フラグが true になりますが、目印だけで、自動で差し戻す仕組みではありません。分岐が見るのは入力の不足・誤りで、金額や承認ではありません。
    • 
        
  • 回答はテスト値　承認・差し戻しは inputs/requests.json に書いたテスト値を、スクリプトが Command で渡したものです。人の承認ではなく、実際の予約・在庫確保・通知・決済もしていません。人が答える画面はこの作例にありません。
    • 
        
  • 同じプロセスのメモリ　チェックポイントは InMemorySaver による同じPythonプロセスのメモリだけで、thread_id で3件を分けました。ディスク・サーバー・クラウドへの保存や、再起動後の再開は試していません。
    • 
        
  • 再開の仕組み　再開すると review ノードが先頭からやり直され、interrupt が回答を返します。そのため interrupt より前に送信などの副作用を置いていません。finalize から始まるわけでも、途中の命令から続くわけでもありません。
    • 
        
  • 使っていないもの　グラフからのLLM・モデルAPIの呼び出し、LangSmith、Cloud、トレース。
    • 
        
  • 元の制作時の確認　元の Opus 5.5 の実行受領は2件（実装と以前の動画）。原典の172ファイルは公式のバイト列と一致し、導入した157ファイルが固定版と一致しました。これは元の制作時の確認で、この紹介の図や動画の確認ではありません。
    • 
        
  • このページがしていること　開くたびに、固定した21件の大きさとSHA-256、記録の中身（6つの引用の行、固定コミットと4パッケージの版、3件の記録と入力・runs.json・samples.json の一致、workflow.py の5ノード・条件分岐・compile・invoke・interrupt・Command の行）を確かめます。合わないときは図も記録も出さずに止まります。HTTPS か localhost で開いてください。
