    部品と、元の行

    使い方

    1. BrowserConfig でブラウザーを決める（今回は Chrome・headless）。
    2. CrawlerRunConfig に、待つ条件・本文の範囲と、2つの出力の設定（DefaultMarkdownGenerator と JsonCssExtractionStrategy）を入れる。
    3. async with AsyncWebCrawler(...) as crawler の中で await crawler.arun(url, config) を呼ぶ。
    4. 戻った markdown と extracted_content をどう使うかは、呼び出す側のコードが決める。今回は workflow.py が元のHTMLと照合し、全体の結果メモにまとめた。

    保存された結果と入力

    • 全体の結果メモ（outputs/result.md）workflow.py が4回の実結果から書いた日本語のまとめ。ページごとの Markdown（response.markdown）とは別物です。
    • 実行結果（outputs/runs.json）4回の arun の保存結果・設定・照合・サーバーの記録。
    • 元の実結果ビューア（desk.html）ページごとの結果 · 準備 · 当日の確認 · 書き出し · 取得エラー · ファイル · 依頼文

    入力（作例用に書いた架空のページ）

    取得に使ったファイルそのものです。保存済みの記録にある 127.0.0.1 のURLは当時の一時ポートで、今は開けないためリンクしていません。

    • fixture/docs/start.html
    • fixture/docs/review.html
    • fixture/docs/export.html
    • fixture/docs/dynamic-export.js書き出しページの2節目を読み込み後に加え、data-ready を true にするページのスクリプト。
    • workflow.pyCrawl4AI を呼んだ元の実装。
