# 解説映像の編集元 — 好みを覚えて、次に引き出す（Mem0 OSS 作例）

架空の2人（`aya`・`ken`）の好みを、固定版 Mem0 のオープンソース版 Memory API に保存した実行記録から、28秒・無音の映像を描く元ページです。`index.html` を開くと、照合したファイルから描いた映像を、再生位置を選んで確かめられます。

主なメッセージは「好みを覚えて、次に引き出す。」です。筋は一本です：人ごとに好みを保存 → `user_id` で絞って検索 → 20秒から30秒へ明示的に更新 → 新しいプロセスでも更新後の本文が同じIDで返る → 8場面の実結果をサイトで読む。

この映像は、保存した実結果と実画面の静止画を編集したものです。APIの実行や操作の連続した録画ではありません。端末・打鍵・AIの思考・生成された会話は、記録にないので描いていません。ページでも映像でも、Mem0・Python・AI は動きません。

## 映像が示すこと・示さないこと

- 7件はすべて `Memory.add(..., infer=False)` で、渡した文を1件ずつそのまま保存しました。LLMによる要点の抽出・重複の統合・回答の生成は使っていません。Memory は設定上LLMのクライアントを必ず作るため、公式の Ollama 設定を閉じたポートに向けて置き、一度も呼んでいません（呼び出し0回）。モデルのサーバーも動かしていません。
- ベクトルは固定版の多言語埋め込みモデル（`e8f8c21`・384次元）がCPUで計算しました。文章を書くモデルではありません。保存先は埋め込み型の Qdrant と SQLite です。
- Mem0 Platform・プラグイン・アカウント連携・ブラウザー内のAIは使っていません。
- `filters={"user_id": ...}` は検索範囲の指定で、**認証や権限の仕組みではありません**。映像の8〜12秒にも注記を出します。
- 20秒→30秒の書き換えは、実行スクリプトが `Memory.update` を明示的に呼んだものです。Mem0 が自動で判断したのではありません。
- 削除（M06）は映像の筋から外しました。削除した記録は取得・一覧・検索から外れますが、SQLite の履歴には削除前の本文と DELETE の行が残ります。物理的な消去は確かめていません。全容はサイトで読めます。開き直し後の件数（aya 3件・ken 3件）は、削除の説明なしでは最初の4件・3件と食い違って見えるため、映像に出しません。
- 検索の質・認証・プライバシー・速さの評価ではありません。実行の所要秒は映像に出しません。検索スコアも読みやすさのために省きました（記録では検索9件すべてが意味の近さだけのスコア）。

見出しの「2人」「30秒」「8つ」も記録から作ります。足元にはいつも「実行記録と実画面を編集・無音」と「aya・ken と好み7件は架空」を表示します。場面は重ねず、終わりの0.25秒で紙の色へ消えてから、次が0.25秒で現れます（境目に約0.5秒の静かな間）。数え上げ・タイピング・進み具合の演出はしません。

ポスター（13.5秒）は、見出し、「20秒 → 30秒」、更新後の句、同じIDと履歴、実画面がすべて着地して止まった状態です（全要素が13.4秒までに着地）。

### 360px幅で読む文字

1280px幅の論理座標で、見出しは明朝72px、主役の「20秒 → 30秒」は最大140px（幅に合わせて112pxまで）、件数は140px、問いと本文の句は40〜48pxです。360px幅に縮めると、見出しは約20px、「20秒 → 30秒」は約35〜39px、句は約11〜13pxになります。30pxの補足と26pxの帯・実画面の注記は、読まなくても筋が分かるように置いています。実画面の中の文字は360px幅では読めない大きさで、補足の証拠として置いています。主な文字は実画面に頼らず編集で描いています。

## 本文の抜粋

抜粋は保存した本文からの文字列そのままで、表示する直前に `video.js` が規則で切り出します。手で書き写した文は使いません。「…」は省略の印で、本文の文字ではありません。全文はサイトで読めます。

| 場面 | 出典 | 切り出しの規則 | 現在の記録での表示 |
| --- | --- | --- | --- |
| 4〜8秒 | M01 get_all の A02・K02 | 「、」「。」を含まず「N秒程度の動画」で終わる部分。前後に「…」 | `…音声なし・20秒程度の動画…` / `…ナレーション付き・60秒程度の動画…` |
| 8〜12秒 | M02・M03 の応答の1件目 | 最後の「、」の後から文末まで（なければ「〇〇さんは」の後）。先頭に「…」 | `…説明は短い段落と箇条書きを好みます。` / `…ナレーション付き・60秒程度の動画で見たいです。` |
| 12〜18秒 | M05 の after.memory | 4〜8秒と同じ。秒数だけコバルト | `…音声なし・30秒程度の動画…` |
| 18〜22秒 | M07 の検索の1件目 | 8〜12秒と同じ。秒数だけコバルト | `…音声なし・30秒程度の動画で見たいです。` |

どれが1件目かは記録のまま描き、コードでは決めていません。IDは先頭8文字と末尾6文字に短縮し（`c29f6400…85d97c`）、更新前後と開き直し後で同じことを照合します。

各文字は決めた大きさのまま枠に収まるかを確かめ、収まらなければ縮めずに理由を出して止まります（「20秒 → 30秒」と冒頭の3語だけは下限まで縮めます）。

## 時間の契約

- `window.motionConfig = {duration: 28, fps: 30, width: 1280, height: 720, posterTime: 13.5, audioEvents: []}`。840フレーム、**無音**です。
- `window.renderConfig` の幅・高さ・FPS を初期化時に反映します。1280×720 を基準に、渡された縦横比へ論理座標を広げ、上の帯と足元の帯は端に、本文は中央に置きます。確認の対象は1280×720だけで、他の縦横比は未確認です。
- Canvas は `getContext('2d', {willReadFrequently: true})` で作ります。
- `window.motionReady` は、フォントの準備、照合表と8ファイルの照合、画像の復号、記録の照合、文字の収まりの確認が済むと解決します。失敗すると理由つきで拒否され、ページは `#status[data-state="error"]`、`#detail` の説明、「もう一度読み込む」（`#reload`）を出します。準備が済むと `#verified` に8ファイルと SHA-256 を並べます。
- `window.seek(seconds)` は、0〜28秒に収めた時刻だけから完成した1フレームを描きます。毎回キャンバスの状態（変換・透明度・クリップ）を捨ててから描き、壁時計・乱数・前のフレームには依存しません。動きは閉形式の減速曲線です。
- 素材のパスは `new URL('../' + path, import.meta.url)` で `video.js` の1つ上（作例フォルダ）を基準に解決します。書き出し時に `<base href="video/">` が入った写しでも同じファイルを指します。外部のフォント・CDN・通信は使いません。
- 編集用のプレビューは停止・0秒から始まり、自動では再生しません（動きを減らす設定でも同じ）。「再生」を押したときだけ requestAnimationFrame で進み、「一時停止」で止まり、最後まで進むと停止に戻ります。書き出し時（`window.__MOTION_RENDER__`）は動かさず、キャンバス以外を隠します。CSS のアニメーションは使いません。
- 再生ボタン `#play` の `aria-pressed` は再生中かどうかを表します。再生位置 `#time` は0〜28秒・0.1秒刻みで、`#clock` に現在の秒を出します。矢印キーは0.1秒、PageUp・PageDown は2秒、Home・End は先頭・末尾です（Home から PageUp 7回で14秒）。操作部品は44px以上、文字は16pxです。

## 開いて確かめる

照合に WebCrypto と fetch を使うため、`file://` ではなくローカルサーバー（または https）で開きます。作例フォルダ（`video/` の1つ上）で次を実行し、`http://127.0.0.1:8866/video/` を開きます。

```powershell
python -m http.server 8866 --bind 127.0.0.1 --directory .
```

## 書き出しの再現

必要なもの：Node.js 20以上、インストール済みの Google Chrome、FFmpeg と ffprobe、Python 3。作例フォルダで次を実行します。依存はレンダラーの隣にだけ入れ、パッケージのスクリプトは実行しません。

```powershell
npm ci --ignore-scripts --no-audit --no-fund --prefix tools/motion-reel
python render.py --out <NEW_EMPTY_OUTPUT_OUTSIDE_SOURCE> --work-root <NEW_PRIVATE_WORKDIR>
```

`render.py` は作例フォルダを `--work-root` の下の一時フォルダへ写し、`video/index.html` に `<base href="video/">` を入れた写しを入口にして、同梱の `tools/motion-reel/render.mjs` を呼びます。出力先と作業用フォルダは作例フォルダの外だけを受け付け、既存の書き出しは上書きしません。静止画・コンタクトシート・ポスター・連続フレームだけを作るときは `--stills-only` を付けます。連続フレームの位置は `--strip-at`（既定8.1秒）で変えられます。たとえば12秒の場面の切り替えを見るなら次のとおりです。

```powershell
python render.py --out <NEW_EMPTY_OUTPUT_OUTSIDE_SOURCE> --work-root <NEW_PRIVATE_WORKDIR> --stills-only --strip-at 12
```

レンダラーは同じ時刻を別の順序と新しいページで描き、PNG の一致を確かめます。これは同じ環境内での再現性を示すものです。書体は環境のものを使うため（Windows では Yu Gothic UI・Yu Mincho・Cascadia Mono か Consolas、macOS では Hiragino と SF Mono）、OS が違えば文字の幅や見た目が変わります。
