        この作例で確かめた範囲
        
    7件はすべて Memory.add(..., infer=False) で、渡した文を1件ずつそのまま保存しました。LLM による要点の抽出・統合・会話は使っていません。ベクトルは固定版の多言語埋め込みモデルが CPU で計算し、保存・検索・更新・削除・履歴は Mem0 の API が行いました。
    
        
    検索の Mem0 スコアは並び順を決める値で、確率や確信度ではありません。図には順位だけを出しています。
    
        
    あやとけんの分離は、アプリが渡す filters={"user_id": ...} による検索範囲の指定です。認証や権限の仕組みではありません。
    
        
    更新（M05）は実行スクリプトが Memory.update を明示的に呼んだ結果です。削除（M06）は記録を取得・一覧・検索の対象から外す操作で、SQLite の履歴には削除前の本文と DELETE が残ります。ファイルからの物理的な消去は確かめていません。
    
        
    開き直し（M07）は、最初のプロセスで保存先を閉じたあと、同じ保存先を新しい Python プロセスで開いた実際の記録です。ブラウザーでの再起動の再現ではありません。
