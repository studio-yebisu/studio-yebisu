# 操作と照合の方法

架空の検索画面「まちの作業席」を、Browser Use（browser-use/browser-use 固定コミット `c75e8476e26d18b7617643bc2ae082fae8eae431`、配布版 0.13.11）の Actor API で操作し、6つの状態を記録する方法です。上流の文書では Actor API は「Legacy Direct Browser Control」と呼ばれ、AI エージェントと組み合わせることもできる低レベルの直接操作です。この作例では直接操作だけを使い、エージェントは使いません。

## 1. 入力

- `input/workspaces.json`：架空の作業席12件。ID・名前・エリア（恵比寿・渋谷・代官山・目黒）・1時間の料金・土曜の利用・電源の有無・説明文。実在の施設・料金・予約ではありません。
- `input/scenarios.json`：6状態の手順（API・セレクター・値）と期待するID。LLM が次の操作を判断した履歴ではなく、事前に書いた手順です。

`run_browser.py` は起動前に2つのファイルの生のバイト列から SHA-256 を計算し、Pydantic v2 の厳密なモデルで形を確かめます。使える操作は次の組み合わせだけで、任意の JavaScript・URL・シェルの指定は受け付けません。

| API | セレクター | 値 |
| --- | --- | --- |
| `fill` | `#search` | 1〜40文字（制御文字なし） |
| `select_option` | `#area` | 恵比寿・渋谷・代官山・目黒 |
| `select_option` | `#budget` | 500・800・1000 |
| `check` | `#saturday`・`#power` | なし |
| `click` | `#apply`・`#reset` | なし |

さらに、手順から求めた条件を検索の規則（下の2.）に当てはめ、期待するIDと一致するかを起動前に確かめます。一致しなければ、入力や期待値を書き換えずに止まります。

## 2. 検索の規則（fixture.js と run_browser.py で同じ）

- キーワード：名前・エリア・説明文をつないだ文字列と、入力した語を、それぞれ NFKC 正規化・小文字化します。空白で区切った語がすべて含まれる席を残します（AND）。文字の一致であって、設備の判定ではありません。
- エリア：選んだエリアと同じ席だけ。
- 1時間の予算：料金が選んだ金額以下の席だけ。
- 土曜に使える・電源あり：チェックしたとき、その項目が「あり」の席だけ。
- 並び順は入力の順。絞り込みは「この条件で探す」を押したときだけ行い、「条件をリセット」は押した時点で全条件を外して12件に戻します。

## 3. ブラウザーの起動

browser_use を読み込む前に、`ANONYMIZED_TELEMETRY=false`・`BROWSER_USE_CLOUD_SYNC=false`・`BROWSER_USE_DISABLE_EXTENSIONS=true`・`BROWSER_USE_SETUP_LOGGING=false`・`BROWSER_USE_CONFIG_DIR=<作業フォルダ内>` を設定します。作業フォルダは既定で `studio-yebisu-browser-use-` で始まる一時フォルダを作り、終わったら、その一時フォルダであることを確かめてから削除します。`--work-dir` で指定したフォルダは削除しません。

プロファイルは作業フォルダ内に新しく作り、既存の Chrome プロファイルは使いません。上流の `profile.py` は、名前に `browser-use-user-data-dir-` を含む `user_data_dir` を一時フォルダへコピーせずにそのまま使うため、この名前を付けています。

`Browser(headless=True, executable_path=<既存のChrome>, user_data_dir=<新しいプロファイル>, enable_default_extensions=False, allowed_domains=[配信元], permissions=[], accept_downloads=False, auto_download_pdfs=False, window_size={'width': 1280, 'height': 900}, viewport={'width': 1280, 'height': 900}, keep_alive=False)` を作り、`start()`、`new_page(<配信元>/fixture.html)`、`set_viewport_size(1280, 900)` の順に呼びます。処理の成否にかかわらず最後に `stop()` を呼びます。ほかのプロセスは終了させません。

## 4. 待ち方

上流の文書のとおり、`get_elements_by_css_selector()` は表示を待たずにすぐ返ります。そこで次のように、最長15秒・0.1秒間隔で問い合わせ直します。決め打ちの待ち時間で準備ができたとはみなしません。

- 読み込み：`#load-status[data-state="ready"]` が1件見つかるまで。`data-state="error"` が見つかったら止まる。
- 操作する要素：セレクターで**ちょうど1件**見つかるまで。2件以上なら止まる。
- 操作のあと：DOM の結果のID・適用中の条件（`#results` の data 属性）・表示し直した回数（`data-revision`）が、手順から求めた値になるまで。

## 5. 操作

各状態で、手順の順に、1件に決まった要素へ `Element.fill`・`Element.select_option`・`Element.check`・`Element.click` を呼びます。値の入力や DOM の変更を JavaScript で直接行うことはしません（上流の実装が内部で行う処理はそのまま使います）。操作の記録（API・セレクター・値）は、呼び出しが成功したあとに追加します。

## 6. 読み取りと照合

`Page.evaluate` は読み取り専用の関数1つだけに使い、次を JSON 文字列で返させて Python で読みます：タイトル・パス・表示領域・読み込みの状態・フォームの値・適用中の条件・表示し直した回数・件数の文字・該当なしの表示・結果カードごとのID・名前・エリア・料金・土曜・電源・説明文と data 属性。

各状態で次をすべて確かめ、一つでも外れたら止まります。

- パスが `/fixture.html`、表示領域が 1280×900
- フォームの値と適用中の条件が、手順から求めた値と同じ
- 結果のIDの並びが期待するIDと同じ
- 各カードの名前・エリア・料金（data-price と「700円」の形の表示）・土曜と電源（data 属性と「土曜：利用可」「電源：なし」などの表示）・説明文が、入力の作業席と同じ
- 件数の表示が「該当 N件」で結果の数と合い、該当なしの表示は0件のときだけ出る

期待するIDは照合にだけ使います。記録する結果は、実際に DOM から読んだ値です。

## 7. 画面

照合が通ったあと `Page.screenshot(format='png')` を呼び、base64 を復号して PNG の先頭（IHDR）から幅と高さを読みます。1280×900 でなければ止まります。画像は `captures/S01.png`〜`S06.png` に新規作成で書き、SHA-256 を記録します。

## 8. 書き出し

6状態がすべて通ったときだけ、`studio-yebisu-browser-run-v1` の JSON を一時ファイルに書き切ってから、既存のファイルを上書きしない方法で置きます。記録には、時刻・手元のパス・ポート番号・環境変数・認証情報を入れません。操作した画面の URL は `fixture.html` と書きます。LLM は作っていないので `llm_calls` は 0、`agent_run` は false です。

## 確かめていないこと

- この文書を書いた時点では、`run_browser.py` はまだ実行していません。インストール・実行・画面の確認・動画は制作側で後から行います。
- Browser Use の自律エージェント（`Agent.run`）、LLM による要素探しや抽出、Cloud は使っていないため、その能力・精度・費用はこの作例からは分かりません。
- `allowed_domains` はブラウザーの移動先を限る設定で、OS 全体の通信を遮断しません。オフラインでの実行は保証しません。
- 上流の操作の実装が、操作中に一時的な強調表示などを画面に出すかどうかは、実行後の画像で確かめます。


## 制作担当による実行後の記録

固定Browser Use0.13.11・Python3.12.9・Chrome155.0.8059.41で実行しました。入力2ファイルのSHA、6状態の実DOM、全結果項目と実PNG6枚を照合しています。成功した直接操作はfill2・select_option2・check2・click5の11回。結果は12→12→4→2→0→12件です。初回の結果は名称表示の調整前の履歴として私的に保管し、S02を「電源」の文字検索と明記して再実行しました。再実行時にナビゲーション直後のDOMノード失効を検出し、操作前のセレクター読み取りだけを期限付きで再取得するよう調整しています。成功JSONは全状態の検証後にだけ書かれます。

Windows IAB Chromiumで同じ検索の6状態、全角空白のAND検索、記録の全6状態の全文・結果・JSON保存・依頼文コピー、実503・壊れたJSON・不正コミットからの再試行を確認しました。6幅の検索画面と記録ページは横はみ出しなし、操作対象44px以上、入力16px以上です。物理iOS/Safari/VoiceOver・人の承認は未確認です。自動照合と実画面のエージェントレビューを、人の承認とは分けます。
