青い防御ヒット

架空のアクションゲームのガードを、文章で依頼しました。AIがブリーフとレシピを書き、Effekseerでビルドし、Godotで実際に描画したフレームを見て直しています。下の画面で、その0.5秒の実際の描画を1フレームずつ確かめられます。

  4. 4見て直す

60FPSで撮った f0〜f30（0〜0.5秒）の31枚です。ブラウザーで効果を作り直しているのではなく、制作時に Godot 4.7 と EffekseerForGodot4 で描画して保存したPNGを順に表示しています。

要所のフレーム

1ガードを依頼する

AIのコーディングエージェントに渡した依頼の形です。効果の部分（【】）を自分のゲームの言葉に置き換えて使えます。この依頼は作例のための架空のものです。

Effekseer VFX スキル（kanaworksai-hue/effekseer-vfx-skill、固定コミット c28919890f0483c0f968a884ea03979803d3b528）の SKILL.md と、そこで必ず読むよう書かれた references を読んでから、次の効果を作ってください。

依頼：【架空のアクションゲームで、攻撃を受け止めた瞬間だけ出る青い防御ヒット。約0.5秒。薄い盾の輪郭→短い白い接点→青い面の波紋→隙間を開けた破片→消失。キャラクターを隠さない。一回のガード反応。】

進め方：まず vfx doctor でこの環境にできることを確かめ、ダウンロードが必要なら実行する前に私に確認してください。ブリーフとレシピを書き、brief-validate・lint・build のあと review でGodotの画像を実際に開いて見てください。1回に直すのは1種類の問題だけにします。仕上がったら review-handoff の指示書を、レシピを見ていない別のエージェントに渡して採点してもらい、overview と effect-verify まで進めてください。

報告：effect-verify が verified: true になったか、開いた画像、各回で直したこと、確かめていないこと（端末での性能、ゲームへの組み込みなど）を分けて書いてください。

4見て直す：f16の破片

1回目の実描画では、冷えた青になるはずの破片が、白く光っていました。接点の白い星のあとに、2回目の白い出来事があるように見えてしまいます。

どちらもGodotの実際の描画を、同じ範囲で切り抜いて拡大しています。

  1. 原因を調べる　原典のコンパイラーは、時間で変わる色（color_curve）をSpriteとModelにだけ書き出します。破片に使ったRingは、外側・中央・内側の3つの固定の頂点色で描かれ、色の変化の指定は無視されていました。1回目の破片は、その頂点色が白だったため白く描かれていました。
  2. 2回目　破片の頂点色そのものを、中央が鮮やかな青、縁が暗い紺になるよう変えました。f16の破片は青くなり、白い星だけがいちばん明るい出来事になりました。
  3. 3回目　青い面のレシピに残っていた、効かない色の指定を消し、説明を実際の描かれ方に合わせました。見た目を変える回ではなく、2回目と3回目の32枚のフレームはすべて同じ画像でした。

青い面の見え方は、色が移り変わるのではなく、流れる模様、穴のあく崩れ方、形の動き、薄れ方で変わります。

任意の改善点として「f2〜f4に、ごく薄い楕円の全体を見せると、最初の輪郭が盾だと分かりやすい」と挙げられました。出すのを止める指摘は残っていません。原典の review-submit・overview・effect-verify で verified: true になっています。

Godotでの呼び出し

原典の TestApi.gd で12項目の確認が通りました。

  • 再生の呼び出しと、置く位置・大きさ
  • 速さと一時停止の反映、止めている間の時計
  • 終わったあとの後片付けと、再生中の一覧からの削除
  • 繰り返し再生、発生源の再開始、停止後の後片付け

飛び道具・ビームの呼び出しと、実機での性能は試していません。

明るい背景

効果だけを見る設定と、明るい背景でも描画して確認しました。明るい背景では、光を足して描く部分が淡く見えます。どんな背景でも同じように読みやすいとは言えません。
