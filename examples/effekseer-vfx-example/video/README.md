# 図解動画のソース（Effekseer VFX スキル）

32秒・30fps・960フレーム、無音の図解動画のソースです。縦長 720×1280 と横長 1280×720 を、それぞれに合わせた配置で描きます。紹介ページ（`../index.html`）と同じ構造図を、同じモジュール（`../concept.js?v=visual-r1`）で描きます。

**状態：** ソースを書いた段階です。まだブラウザーで描画しておらず、テスト・フレームの確認・MP4への書き出し・公開もしていません。それらは後の工程で、この README はそれが通ったとは主張しません。この紹介の図と動画には、新しい独立レビューも採点もありません。

## 動画が伝えること

Effekseer VFX スキルが何か（AIが読む手順・参照と、PythonのCLI／コンパイラー）、中に何があるか、依頼と手順がどう制作AIと実際の道具に渡るか、何が返ってきてどう使えるかを、ひとつのつながった図の動きで見せます。

| 秒 | 場面 | 動き |
|---|---|---|
| 0–4 | 手順書 | 本が開き、6つのタブが出る（説明用の整理で、原典の形式や6人のAIではない） |
| 4–8 | 依頼 → 制作AI | 5つの時間の区切りを書いた依頼と手順書が制作AIへ。同じ紙が設計メモとPythonレシピになる |
| 8–14 | レシピ → Core → Godot | 15項目の層（点線の2つは見えない基準点）と5テクスチャが制作担当のCoreへ。.efk がGodotへ渡り、保存した f0〜f30 を元の0.5秒の速さで1回、次にゆっくり見せ、f10 で止める |
| 14–20 | 見て直す | 実画像がループで目と制作AIに戻る。1回目 f16（白い破片）→ 2回目 f16（青い破片）→ 3回目は同じ画 |
| 20–26 | 別のAI | 実画像と採点基準だけが別のAIへ（レシピは渡さない）。レビュー → 証拠確認 → 効果一式。f10 を大きく1.5秒以上 |
| 26–29 | 使う | 効果一式が「開く / 保存して使う」へ |
| 29–32 | 全体 | 図全体が止まったまま。動きは28.9秒で終わり、ポスターは31秒 |

場面へ移動するボタンは 0・4・8・14・20・26・29 秒です。

## 実際の素材

- 効果の画像は、元の制作で Godot 4.7（Forward+）と公式 EffekseerForGodot4 1.80.5.1 が描画して保存したPNGだけです：`../assets/frames/guard-f000.png`〜`guard-f030.png`、`guard-f036.png`、`../assets/first-pass-f016.png`（すべて1280×800）。
- 切り抜きは元の `styles.css` と同じ範囲です（防御側 x240 y296 360×288、f16の比較 x290 y330 270×240）。描き直しではありません。
- 時刻はそのPNGのフレーム番号÷60で表示します（例：f10 · 0.167秒）。動画の秒ではありません。
- 本・紙・歯車・目・フォルダーの形と、レシピの色見本は説明用の絵で、エンジンが動いた証拠ではありません。

## 読み込みと止まり方

`../concept/manifest.json`（SHA-256 `605460bc81b15be72ca2c52eb2f04df8c63d74a9b06411f066b72e463de1c233`）が挙げる51件を、大きさとSHA-256で確かめてから描きます。6つの引用の行（CRLFも考慮）、固定コミット、ライセンスと通知、32件の撮影記録、15項目のレシピ、7場面のブリーフ、元の実行記録も中身で確かめます。これらは保存した記録を読む確認で、新しいビルド・描画・レビューではありません。

PNG 33枚は一度だけ読み込み、紹介ページと同じコードを使います。合わない・読めないときは何も描かず、操作を止めて「もう一度読み込む」だけを残します。`crypto.subtle` が必要なので、HTTPS か localhost で開いてください。

## 書き出し側との約束

- `window.motionConfig = {duration: 32, fps: 30, width, height, posterTime: 31, audioEvents: []}`
- `window.renderConfig` の幅・高さ・fps を初期化時に使います。幅が高さより大きければ横長の配置です。`?orient=wide` でも横長になります。
- `window.motionReady` はフォントと51件・33枚の準備を待ちます。
- `window.seek(t)` は時刻 t だけから1枚を描きます。呼ぶ順番や壁時計、乱数、前のフレームに依存しません。毎フレーム canvas を save/restore します。
- `window.__MOTION_RENDER__` が真なら確認用の再生を止め、`?render=1` か `__MOTION_RENDER__` で canvas だけを表示します。
- 音声はありません（音の要素・スクリプト・素材・トラックなし）。

## 確認用の画面

`index.html` を開くと、再生・最初へ・最初から再生・最後へ、0〜32秒の位置、7つの場面ボタン、縦長／横長の切り替えがあります。これらは確認用で、書き出す映像には入りません。以前の28秒の解説動画のソースは `legacy.html` と `scene.js` に、元のまま残っています。

## この作例のほかの事実

- 効果は架空のガード1つ（VFX_Yebisu_Guard）、0.5秒・60FPS、乱数の種1729、粒子の上限27（上限であって性能の測定ではない）。
- 元の別のAIは画像の引き継ぎ書と採点基準だけを受け取り、レシピや作者の経緯は見ずに ship と判定しました。任意の提案（f2〜f4の薄い楕円）は元の効果に入れていません。
- 元の effect-verify の `verified: true` は、固定したレシピ・描画・レビュー・証拠の対応の確認です。人の承認、見た目の保証、端末での性能、ゲームへの組み込みではありません。
- `effect-library.zip` は元のライブラリ28件と README・LICENSE・通知の31件です。ゲームの完成品ではなく、ゲームでの動作は試していません。保存した一式に `verified: true` は引き継がれません。
