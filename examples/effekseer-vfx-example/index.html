このスキルは何か

Effekseer VFX は、AIが読むMarkdownの手順・参照と、PythonのCLI／コンパイラーの組み合わせです。公式の Effekseer Core と Godot の確認用 Lab につながり、採点には別のスキル vfx-review を使う別のAIが入ります。AIモデルでも、画像・動画を作るAPIでも、ブラウザーで動く描画エンジンでもありません。

図の流れ

  1. 渡す　手順書と、5つの時間の区切り（輪郭→接点→波紋→破片→消失）を書いた依頼が「制作AI」へ。AIが設計メモとPythonレシピを書きました。レシピは15項目で、うち2つは見えない基準点です。
  2. 作って見る　制作担当がレシピと5つのテクスチャを公式の Effekseer Core でビルドし、同じファイルを Godot で描画。AIはその実画像を見て、1回に1種類だけ直しました（全3回）。
  3. 使う　実画像と採点基準だけが別のAIへ（レシピは渡していません）。そのレビューは原典の証拠確認で効果一式に結びつき、31枚を開いたり、一式を保存して使ったりできます。

AIが執筆　元の Opus 5.5 がブリーフとレシピを書き、制作担当が撮った画像を見て直しを書きました。制作担当が実行　doctor・brief-validate・lint・build・review・review-handoff／review-submit・overview・effect-verify と Godot の TestApi は、制作担当が別の工程で実行しました。図には、AIがコマンドを実行する場面を描いていません。

この図は構造の説明で、新しい実行の記録ではありません。いまのブラウザーは保存したデータとPNGを読むだけで、Python・Effekseer Core・Godot・AIの推論を動かさず、新しい効果も作りません。本・紙・時計・歯車などの形は説明用の絵で、効果の画像はすべて Godot で描画・保存したPNGです。

中身を6つに分けて見る

6つは説明のための整理で、原典の共通の形式ではありません。6人のAIがいるわけでもありません。押すと図の該当箇所が光ります。

確かめたこと

元の制作時の記録

  • 別のAIのレビュー　レシピも制作の経緯も見ていない別のAIが、画像の引き継ぎ書と採点基準だけを見て ship と判定しました。人による承認ではありません。任意の提案（f2〜f4にごく薄い楕円の全体を見せる）は、元の効果に入れていません。
  • effect-verify　元の固定したレシピ・描画・レビュー・証拠が互いに対応しているという確認で、verified: true です。見た目の良さ、端末での性能、ゲームへの組み込みを保証するものではありません。
  • Godotの呼び出し　原典の TestApi.gd で12項目が通りました（記録では一部をまとめて11の名前）。飛び道具・ビーム・端末での性能は試していません。
  • f16の破片　1回目の実描画では破片が白く光っていました。原典のコンパイラーは時間で変わる色（color_curve）を Sprite と Model にだけ書き出し、Ring は外・中・内の固定の頂点色で描きます。そこで2回目に破片の頂点色を青と紺に変えました。3回目は効かない指定を消して説明を合わせた回で、2回目と3回目の32枚はすべて同じ画像です。面の見え方は色の変化ではなく、流れる模様・穴のあく崩れ方・形・薄れ方で変わります。

このページがいましていること

開くたびに、固定した51件の大きさとSHA-256、記録の中身（6つの引用の行、固定コミット、ライセンス、32件の撮影記録、15項目のレシピなど）を確かめ、PNG 33枚を一度だけ読み込みます。新しいビルド・描画・レビュー・採点はしていません。この紹介の図と動画も、新しいレビューは受けていません。
