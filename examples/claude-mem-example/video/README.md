# Claude-Mem 作例・解説動画の編集ソース

28秒・無音・1280×720・30fps の解説動画です。伝えることは一つ、「前回の判断を、必要な分だけ取り出す。」

保存済みの実行記録と実画面だけを使い、Claude-Mem でメモを取り出す順番を見せます。保存した5件のメモから、まず題名だけ、次に前後の文脈、最後に選んだ1件の本文を開きます。続けて、同じ問いを別のプロジェクトに渡した場合と、新しいプロセスで開き直した場合を見せます。偽のログや端末画面は使わず、AI がその場で動いているようにも見せません。

| 項目 | 状況 |

| Claude-Mem の実行（`outputs/memory-run.json`） | 制作側が改変していない上流関数を Bun で実行して記録 |

| フレームの書き出し・MP4・再生確認・映像レビュー | 制作側が840フレーム・全デコード・28秒実再生・代表/連続/360pxフレームを確認 |

| 掲載先 | 既存のStudio Yebisu GitHub Pages。反映後の実URL・デモ・動画を確認してから制作キューを完了にする |

自動確認の件数や同じ時刻の画像の一致は技術的な確認です。映像の出来や人の承認を示すものではありません。

## 素材と照合

`video.js` は次の順に照合し、どれかが合わなければ `window.motionReady` を失敗させます。失敗時は理由を画面に出し、映像は描きません。記録が読めないときに代わりに使うデータは、コードに入っていません。

1. `assets/data-hashes.json` を読み、SHA-256 が `4c008abd6a277b3a518f069ec7769762a76cf2e60f22810df7443739c9254d5c` と一致するか確かめる。
2. その中の8件を、`new URL('../' + キー, document.baseURI)` で同じ場所から読み、SHA-256 を比べる。

3. 記録の中身を確かめる。対象は、形式、原典のリポジトリ・固定コミット・版・ライセンス・NOTICE、vendor-lock の194ファイル、入力のハッシュ、Bun 1.4.3、自動確認99件の全合格、通信・サーバー・プロセス起動の試みが0件であること、新しいプロセスが終了コード0だったこと。
4. 各場面の値を確かめる。C01 は0件。C02 は5件（3＋2）で、再送は同じ ID の duplicate。C03 は題名だけの索引。C04 は選んだ記録と前後の題名。C05 は本文1件で、内容が保存したメモと一致。C06 は2つのプロジェクトでそれぞれ別の1件。C07 は新しいプロセスで同じ ID と同じ件数が返り、前の合図は `invalid_continuation`。C08 は4つの拒否と、未登録のプロジェクトで0件。独立した SQLite 監査（`independent-checks.json`）とも突き合わせる。
5. 画面写真2枚を画像として読み、`screens.json` に記された大きさ（375×812 と 1265×949）と一致するか確かめる。

画面に出る題名・ID・本文・件数・段階の名前は、すべて照合した記録から読みます。C05 で大きく出す一文は、返ってきた本文の2文目そのもの（「ボタンは44px以上にし、本文をバーで隠さない。」）で、「本文から抜粋」と表示します。生成した回答ではありません。

編集画面の「素材8件の SHA-256 照合」（`<details id="asset-checks">`）を開くと、8件それぞれの照合結果を確かめられます。

## 画面写真

`assets/phone.png`（375×812、C05）と `assets/desktop.png`（1265×949、C03）は、Studio Yebisu の閲覧ページを Chromium（IAB）で撮影したものを、1バイトも変えずに写したものです。映像では縦横比を保ったまま全体を収めます。切り抜き・描き足し・隠し・ラベルの付け替えはしていません。Claude-Mem 公式の画面ではないため、説明文では「閲覧ページの実画面」と呼びます。実機の iOS では確かめていません。

## 試した範囲

試したこと：

- 手で保存した架空の5件のメモ（`saveMemory`）
- SQLite FTS5 のキーワード検索
- mem_search の段階的な検索（guided と auto）を、上流のワーカー関数（`DatabaseManager`・`SearchManager`・`ProgressiveMemorySearch`・`progressiveSearchToolResult`）に直接使う。Bun のプロセス1つと、新しいプロセス1つ
- mem-search の SKILL の手順は、MCP サーバーにつないだのではなく、ワーカー関数に直接当てはめた

試していないこと（主張もしない）：

- プラグインの導入、フック、会話の自動記録、LLM による要約、文脈の自動挿入
- Chroma の意味検索、クラウド、ホスト型の記憶
- MCP の通信、Claude の推論
- 認証やアクセス制御。`project` は検索範囲を分けるだけです
- あらゆる攻撃への耐性。C08 は記録した4種類の誤りが拒まれたことだけを示します
- 実機の iOS

`ms_` で始まる続きの合図は、発行したプロセスの中だけで15分有効です。メモは SQLite に残りますが、合図は残りません。そのため、映像では合図の文字列を出していません。

C08 は、実際の実行では C07 より先に動かしています。C03 の合図がまだ有効なうちに拒否を確かめるためです。公開する場面の順番 C01〜C08 は、この事実と矛盾しません。

## 時刻と場面

| 時刻 | 場面（記録） | 見出し | 入り | 止まって読める時間 | 出 |
| --- | --- | --- | --- | --- | --- |
| 0〜4秒 | 1（C01・C02） | 前回の判断、どこだっけ。 | 見出し 0.15〜0.55秒。5枚のカードが保存順に 0.5〜1.78秒で落ちる。件数が0から5へ | 約1.9秒（1.8〜3.65秒） | 3.65〜4.0秒 |
| 4〜8秒 | 2（C03） | まず、題名だけ。 | カードが索引の2行へ（4.0〜4.45秒）。返ってきた順は N02、N01。大きな「2 題名」と「0 本文」 | 4.45〜7.65秒。5.6秒に、呼び出し側が N01 を選んだ印 | 7.65〜8.0秒 |
| 8〜12秒 | 3（C04） | 前後を見て、選ぶ。 | 文脈の順（N01、N02）に並べ替え（8.0〜8.45秒）。「0 本文」に下線、「前後1件まで」 | 8.9〜11.7秒 | 11.7〜12.0秒 |
| 12〜18秒 | 4（C05） | 選んだ1件の本文へ。 | N01 のカードが広がり本文が出る（12.0〜12.85秒）。スマホの実画面と抜粋 12.5〜13.2秒。本文中の下線 12.9〜13.3秒 | 13.3〜17.65秒（ポスターは13.5秒） | 17.65〜18.0秒 |
| 18〜22秒 | 5（C06） | 同じ問いを、別の案件へ。 | 同じ問い「iOS」から2枚へ（18.05〜18.7秒）。題名の違う部分に下線 18.7〜19.1秒 | 19.1〜21.65秒 | 21.65〜22.0秒 |
| 22〜25.4秒 | 6（C07） | 次のプロセスでも、同じメモから。 | N01 が SQLite に収まり、N02 が新しいプロセスから出る（22.0〜22.95秒）。「5件のまま」、ID 2 に下線、前の合図に取り消し線（23.45秒まで） | 23.45〜25.05秒 | 25.05〜25.4秒 |
| 25.4〜28秒 | 7（C01〜C08） | 前回の判断を、必要な分だけ取り出す。 | 「8場面の実記録で確かめる。」、実画面2枚、8場面、URL、原典（25.4〜25.85秒）。下線は26.0秒まで | 26.0〜28.0秒の2秒間、完全に静止 | なし |

場面6の見出しは、ブリーフの案「次のプロセスでも、続きから。」から変えました。新しいプロセスでは前の続きの合図が拒まれるため、「続きから」では誤解を招くからです。引き継がれるのはメモです。

切り替えは 4・8・12・18・22 秒の前後に置き、0.35〜0.5秒で落ち着かせます。画面全体を白や黒に飛ばすことはしません。N01 のカードは 0〜22秒で同じ1枚として動き続けます（小さなカード → 索引の行 → 文脈の行 → 本文 → 範囲 → SQLite）。カードの黄色い丸の数字は、段階に合わせて 1 → 2 → 3 と進みます。

文字の大きさ（1280幅のとき）：見出し 60px（締めの一文は 56px）、主な数字 150px（場面6 は 120px、本文0件は 96px）、抜粋と締めの行 40px、本文 22px。メタ情報・ID・画面写真・原典の表示は 14〜17px の補足で、読めなくても話が通じる作りにしています。

## 編集画面の操作

| ID | 役割 |
| --- | --- |
| `#play` | 再生。再生中は押せない |
| `#pause` | 一時停止。停止中は押せない |
| `#reset` | 0秒に戻して停止 |
| `#scrub` | 時刻のスライダー（0〜28、0.1刻み）。動かすと停止してその時刻を描く |
| `#time` | 秒の数値入力（0〜28、0.1刻み、16px） |
| `#time-label` | 現在の時刻の表示 |
| `#editor[data-state]` | `paused` または `playing` |
| `#scene-list` | 場面ごとのボタン。押すとその場面の読める時刻で止まる |
| `#asset-checks` | 素材8件の SHA-256 照合結果 |
| `#status`・`#error-box` | 読み込み状況と失敗の理由 |

開いた直後は0秒で停止しています。再生は `requestAnimationFrame` の時計で `window.seek(絶対時刻)` を呼ぶだけで、一時停止すると止まります。ボタンや入力欄は44px以上、入力の文字は16pxです。320〜390px の幅でも折り返して並び、拡大縮小もできます。

`file://` では素材を読めません。site フォルダーを HTTP サーバーで開き、`video/index.html` を表示してください。

## 合成の契約

- `window.motionConfig = { duration: 28, fps: 30, width: 1280, height: 720, posterTime: 13.5, audioEvents: [] }`。最初に渡された `window.renderConfig` の幅・高さ・FPS を使います。作っているのは横長 1280×720 だけで、縦長や正方形の構成は用意していません。
- `window.motionReady`：素材の照合、記録の確認、画像の読み込み、手元の書体（`document.fonts.ready`）を待ちます。
- `window.seek(秒)`：0〜28 に収め、その時刻の画面を描き終えてから解決する Promise を返します。描画は時刻だけから決まり、前のフレーム・壁時計・乱数には依存しません。28秒の画面は26秒以降と同じ静止画です。
- `window.__MOTION_RENDER__ === true` のとき：操作部品を隠し、キャンバスだけを指定の大きさで出します。プレビューの再生は動きません。
- キャンバスは `getContext('2d', { willReadFrequently: true })`。CSS アニメーションは使っていません。

## 書き出し（制作側が実行）

site にある既存の `render.py` と、同梱の Motion Reel レンダラー（`../tools/motion-reel/render.mjs`）を変えずに使います。

必要なもの：Windows、Python 3.9 以上、Node.js 20 以上、Google Chrome（既定では Playwright の `chrome` チャンネル）、PATH の通った FFmpeg と ffprobe。`../tools/motion-reel/node_modules` がなければ、そのフォルダーで一度だけ `npm ci --ignore-scripts` を実行します。

```text
cd <site>/video
python ../render.py --out <site の外の、新しい空のフォルダー> --work-root <site の外の作業フォルダー>
```

- `render.py` は site を `--work-root` の下の使い捨てフォルダーへ写し、`video/index.html` を入口にして（`<base href="video/">` を足す）、`node ../tools/motion-reel/render.mjs --project <写し> --out <出力> --step 2 --strip-at 8.1 --video` を呼びます。
- 音のオプション（`--synth`・`--audio`）は使いません。MP4 は音声トラックなしになります。
- 出力：`video.mp4`（1280×720、30fps、840フレーム、28秒、音なし）、`poster.png`（13.5秒）、`contact.png`（2秒ごと14枚）、`strip.png`（8.1秒前後の連続12フレーム）、`capture.json`（同じ時刻を別の順番と新しいページで描いた一致の記録）、`review.html`。
- 静止画だけなら `--stills-only`。連続フレームの位置は `--strip-at 12.1` などで変えられます。
- 出力先は毎回、空の新しいフォルダーにしてください。既存の書き出しは上書きされません（空でなければ止まります）。

今回制作側が確かめたこと（再実行時も確認してください）：全体シートで情報の順序と文字の重なり、連続フレームで切り替えの動き、360px 幅での見出し・数字・抜粋の読みやすさ、MP4 の通し再生。
