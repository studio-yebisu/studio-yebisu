# 入力ファイルについて

このフォルダーの2つの JSON は、run.ts が実行の前に SHA-256 で照合する、固定された入力です。どちらも Studio Yebisu の制作側が実行の前に書いたもので、Claude Opus 5.5 が書いたものではありません。

| ファイル | 内容 | SHA-256 |
| --- | --- | --- |
| `notes.json` | 架空の5つの決定。「さくらサイト」（sakura-site）3件、「つばき資料」（tsubaki-docs）2件。キー・プロジェクト・題名・本文 | `615600356841c0f3a7d8bf55773f2a6869da320a9c03ae2c9552df15be38e5f3` |
| `scenarios.json` | 8つの場面 C01〜C08 の問い・プロジェクト・モード・件数・拒否の種類 | `29f4d0ad731aae355a160a6896c799af502236221f7bff2736038f5a044fd3fd` |

5件はすべて架空です。実際の会話、個人の記録、保存したブックマークなどは含みません。run.ts はこれらを読むだけで書き換えず、実行の最後にもう一度ハッシュを計って、変わっていないことを確かめます。

## 自分の架空データで試すとき

1. 作業フォルダーを丸ごとコピーし、コピーの中で作業します。
2. `notes.json` と `scenarios.json` を書き換えます。実在の人の記録や秘密情報は入れないでください。
3. 書き換えたファイルの SHA-256 を計り、`run.ts` の `INPUT_SHA256` と `app.js` の `FROZEN.inputs` に入れます。これで入力が固定されます。結果を見てから入力を変えないでください。
4. 場面の中身に合わせて、run.ts の確認（期待する ID の組み合わせや件数、場面ごとの確認の数 `EXPECTED_CHECKS`）を直します。確認を外して通すのではなく、新しい入力で成り立つべき条件を書いてください。
5. コピーの `outputs/memory-run.json` を消してから、`bun --no-install run.ts --artifact-dir <フォルダーの外の新しい空フォルダー>` を実行します。

検索は SQLite FTS5 のキーワード一致です。FTS5 の unicode61 は日本語の文を語に分けません（上流には、日本語などの問いを部分一致で探す処理があります）。この作例では題名に英字の語（iOS・JSON・PDF・playsinline）を入れてその語で探し、日本語の検索品質は評価していません。
