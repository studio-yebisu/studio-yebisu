# 手順と読み方

この作例は、[Train LLM From Scratch](https://github.com/FareedKhan-dev/train-llm-from-scratch/tree/bdd480a518094ca834e05ab32131dc126b522d3d)（固定コミット bdd480a、MIT、Copyright (c) 2025 Fareed Khan）の学生向けCPUトラックを、原典のコードのまま、作例のために書いた英文96行で実行するものです。ここでは、何を実行し、記録の数字や文章をどう読むかを説明します。実際の値は `outputs/training-run.json` にあり、この文書には書きません。

`run.py` とこの文書は Claude Opus 5.5 が書きました。続きの文章を生成するのは、この作例で学習した小さなTransformerです。

## 1. 何を学習しているか

言語モデルは、文をトークン（文字や単語の断片を表す番号）の列にして、「ここまでの列の次に来るトークン」を当てる練習を繰り返します。予想の外れ具合を数えるのが損失（交差エントロピー）で、正解のトークンに付けた確率 p に対して −ln p です。

出力の候補が V 通りあって、どれにも同じ確率を付けると損失は ln V になります。原典のガイドが「最初の損失は ln(4096) ≈ 8.3」と説明しているのはこのためで、それより下がった分がモデルが学んだ分です。この作例では V が実行で決まるので、ページは記録の値から ln V を計算して添えます。

## 2. データとBPE

```text
python vendor/train-llm-from-scratch/scripts/prepare_tiny_data.py \
  --dataset text --input input/stories.txt --tokenizer bpe \
  --vocab_size 512 --val_frac 0.125 --out_dir <artifact-dir>/data
```

- **分割**：原典の `split_text` は、ファイルの長さの87.5%の位置より手前で最後の改行を探し、そこから先を検証側にします。学習側・検証側はそれぞれ1つの文書で、末尾に区切り記号 `<|endoftext|>` が付きます。
- **BPE**：256通りのバイトから始め、学習側の文でいちばん多く隣り合う組を1つの番号にまとめる、を繰り返します。語彙512の指定は「最大で255回まとめ、区切り記号を1つ足す」という意味です。短い型の繰り返しでは、まとめられる組が先に尽きることがあります。そのときは原典の学習がそこで止まり、語彙は512より小さくなります。実際の語彙数とまとめた回数は記録の `dataset` にあります。
- **埋め込みの余り行**：学習スクリプトは語彙数を64の倍数に切り上げてモデルを作ります（`round_up`）。語彙数が64の倍数でなければ、語彙の外にある余りの行ができ（記録の `model.padding_rows`）、それも出力の候補に含まれます。学習前のモデルがその番号を選ぶこともあります。
- **確かめること**：`run.py` は、HDF5が1次元の int32 で番号が語彙の範囲にあること、原典の `split_text` で分けた文を同じトークナイザーで符号化した列（区切り記号を含む）と完全に一致すること、学習側の文だけでBPEを学び直すと保存された語彙と一致することを確かめます。96行全体で学び直した場合に語彙が同じになるかも事実として記録します。この英文では検証側の行が学習側にもあるため、同じになっても不思議ではありません。

## 3. モデル

`--preset tiny --arch modern` を使い、文脈の長さだけを128から64に縮めます（`--set context_length=64 --set t_context_length=64`）。64次元・4ヘッド・2ブロックで、回転位置埋め込み（RoPE）、RMSNorm、SwiGLU、入力の埋め込みと出力層の重みの共有を使う、原典の「modern」の作りです。事前学習済みの重みは使いません。パラメータ数とテンソルの一覧は記録の `model` にあります。

原典のデータローダーは、トークン列を64トークンずつの窓（先頭が64の倍数の位置）に区切り、毎周シャッフルしてバッチにします。検証側の窓がバッチの16本より少ないときは、その本数だけのバッチになります（記録の `dataset.dev_eval_batch_rows`）。

## 4. 学習前と学習後

```text
python vendor/train-llm-from-scratch/scripts/train_transformer.py \
  --preset tiny --arch modern --device cpu --threads 4 \
  --train-path <artifact-dir>/data/train.h5 --dev-path <artifact-dir>/data/val.h5 \
  --batch-size 16 --lr 0.002 --eval-every 100 --seed 2201 \
  --set context_length=64 --set t_context_length=64 --set t_eval_iters=10 \
  --sample '' --steps 0 --out-path <artifact-dir>/models/baseline.pt
```

2回目は同じ引数で `--steps 800 --out-path <artifact-dir>/models/trained.pt --checkpoint-every 200 --checkpoint-dir <artifact-dir>/checkpoints --keep-last 4` です。

- **学習前（--steps 0）**：学習ループが一度も回らず、最適化の更新なしでモデルを保存します。`run.py` は、保存された記録の更新回数が0で損失の配列が空であること、同じseedで新しく作ったモデルと重みが完全に一致することを確かめます。
- **学習（--steps 800）**：AdamW、学習率0.002。原典は800回の80%（0から数えて640回目）の更新のあとで学習率を1/10の0.0002に下げます。勾配のノルムは1.0で切ります。
- **同じ設定**：2回の設定の違いは、更新回数・学習率を下げる時点・保存先の3つだけです。`run.py` はチェックポイントに保存された設定を突き合わせて確かめます。
- **重みのSHA-256**：テンソルの名前の順に、名前・型・形・バイト数と生のバイト列をつないで計算します。保存ファイル全体のハッシュとは別で、学習前後で値が違うこと、800回目の保存点と学習後のモデルで一致することを確かめます。

## 5. 3種類の損失

| 記録の場所 | 何の値か | 読み方 |
| --- | --- | --- |
| `training.losses`（800個） | 各更新で使った16本の学習ミニバッチの損失 | 更新ごとの値なので上下にぶれます。検証損失ではありません。ページのグラフはこの配列です |
| `training.checkpoints[].periodic_eval` | 0から数えて100の倍数の回（0, 100, …, 700）に、学習側・検証側それぞれ10バッチで測った平均 | 保存点（200・400・600・800回）には、その前の直近の定期評価が入ります。保存点そのものの時点の値ではありません |
| `training.before` / `training.after` | 原典が学習の最後に `estimate_loss(..., 200)` で測った、学習側・検証側それぞれ200バッチの平均 | ページの「学習前の検証損失」「800回更新後の検証損失」はこの値です |

検証側は同じファイルの末尾で、学習側と同じ型・同じ語彙の行です。この英文では検証側の行が学習側にもそのまま含まれます（記録の `dataset.val_lines_identical_to_a_train_line`）。検証損失が下がっても、知らない文への汎化や、文章の品質が上がったことは示しません。

## 6. 生成

8つの書き出しは学習の前に `input/prompts.json` に固定しました。学習前と学習後の両方に、同じ条件で渡します。

- **手順**：書き出しごとに `torch.manual_seed(2201)` を設定してから、原典の `generate_text.load_trained_model` でチェックポイントを読み、`model.generate`（新しく48トークン、温度0.8、top_k 1、窓64トークン）で続け、原典の `safe_decode` で文字にします。順番は `generate_text.py` の main と同じです。
- **top_k 1**：毎回いちばん確率の高いトークンだけを残すので、温度0.8を掛けても選ばれるトークンは変わりません。同じモデルと同じ書き出しなら、同じ続きになります。
- **全文**：記録の `text` は、書き出しを含む全文を `safe_decode` で戻したもので、削ったり整えたりしていません。`token_ids` は書き出しと生成の全トークンです。
- **文字化けに見える部分**：`safe_decode` は語彙の外の番号（埋め込みの余り行）を文字にせずに飛ばします。区切り記号の番号は `<|endoftext|>` という文字列のまま出ます。単独では正しいUTF-8にならないバイトは置換文字（�）になります。どれも番号は `token_ids` に残り、件数は `ids_skipped_in_text`・`endoftext_tokens`・`replacement_chars` にあります。
- **CLIとの照合**：P01 は学習前・学習後それぞれで `generate_text.py` のCLIも実行します。CLIは見出しの行と `--- sample 1 ---` の行のあとに本文を print し、最後に改行を1つ足します。`run.py` はその1つだけを外して、APIの全文と1文字も違わないことを確かめます。Windows の print が改行を `\r\n` に変える場合は、CLI自身が出した見出しの行から判断して元に戻すので、モデルが出した `\r` はそのまま比べられます。

## 7. 記録に残す確認

`run.py` の確認が1つでも通らないか、どれかのコマンドが0以外で終わると、`outputs/training-run.json` は書かれません。確認の名前は記録の `checks` にあり、ページの「実行時に確かめたこと」に日本語で並びます。主なものは次のとおりです。

- 入力3ファイルと原典48ファイルのSHA-256が、実行の前後で固定値と一致する
- HDF5・トークナイザー・分割が原典の処理と一致し、96行全体と8つの書き出しが符号化して戻せる
- 学習前は更新0回、学習後は800回で、損失がすべて有限の値。設定・テンソルの名前と形・トークナイザーが2つのモデルで一致する
- 重みが学習で変わり、200・400・600・800回の保存点がそろい、保存点の損失の列が最終の列の先頭と一致する
- パラメータ数と最後の損失が学習CLIの表示と一致し、P01 の生成が生成CLIの全文と一致する
- 公開フォルダのファイルが増えも変わりもせず、非公開の保存先に予定したファイルだけがある

## 8. 限界

- 英文は作例のために書いた小さな繰り返しの英語で、日本語や実在の文章ではありません。結果は、この英文と設定での1回の実行です。
- 検証損失はテンプレートと語彙を共有する同じファイルの末尾で測った値で、知識・汎化・文章の品質のベンチマークではありません。
- 学習した小さなモデルは、学習文にない書き出し（P07・P08）にも学習文の型や崩れた続きで答えることがあります。質問に答える仕組みはありません。
- SFT・報酬モデル・DPO・PPO・GRPO・RLHF・量子化・ベンチマークは使っていません。
- 所要秒は実行したPC1台の経過時間です。原典のガイドにある速度や損失の値を、このPCの結果として扱いません。
- ページは保存した記録を読むだけです。表示の確認は制作側のブラウザーで行い、物理的なiPhoneのSafariやVoiceOverでは確かめていません。
