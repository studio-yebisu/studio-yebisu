ひとつのMarkdown原稿から、A4と細いページの2種類のPDFをつくる

    原稿：両方の版で同じMarkdown

    A4版と細いページ版は、同じ inputs/event.md から書き出します。原稿の日付・時刻・定員・持ち物などは inputs/event.json の内容だけを使い、表は使わず段落・箇条書き・番号付きリストで組んでいます。

    実行の順序：操作 → API → 出力 → 全ページ確認

    1. 操作

      原稿は1つだけ用意し、版ごとに原典テーマと和文の追加CSSを組み合わせます。A4版は warm-terra ＋ themes/japanese-a4.css、細いページ版は mobile ＋ themes/japanese-phone.css。バックエンドはどちらも chrome を明示します。

      再現用のコマンド（例のルートで実行し、新しいフォルダへ書き出す。公開する build_pdfs.py の既定経路を実行して確認済みです）：

      python build_pdfs.py --out renders/pdf-first

    2. API

      生成スクリプトは、原典の scripts/md_to_pdf.py にある markdown_to_pdf() を呼びます。原典の処理は、Pandoc で Markdown を HTML にし、テーマCSSと表用のCJKパッチを埋め込み、ヘッドレス Chrome でヘッダー・フッターなしのPDFにする流れです。この作例は、原典CSSの後ろに和文CSSを追加し、HTMLを lang="ja" にします。変換を呼ぶ build_pdfs.py には、WindowsでのChrome検出・一時プロファイル・UTF-8読み取りも補っています。可変フォントは太さ400/700/800の静的TrueTypeへ一時展開してからPDFへ埋め込み、原典と原稿は実行中に書き換えません。

    3. 出力

      A4版は outputs/atelier-a4.pdf、細いページ版は outputs/atelier-phone.pdf。各ページを画像にしたPNGを assets/ に置き、ページ数・サイズ・SHA-256 を outputs/manifest.json に記録します。ページ数は生成後に数えた値で、事前に決めてはいません。

    4. 全ページ確認

      原典 SKILL.md の「Visual Self-Check」に従い、全ページの画像を原稿と見比べ、欠け・はみ出し・見出しの孤立・改ページ・括弧や句読点の位置を確かめます。あわせて、PDFから取り出した文字と原稿の文言、埋め込みフォントを照合します。原典の文字組みの自動チェックは中国語向けの一部のパターンだけを見るため、和文の確認はこれとは別に行います。原稿に表がないため、表の罫線チェック（check_table_borders.py）は対象外です。

      確認の記録は、生成後に outputs/manifest.json から参照します。

    再利用できる依頼文

    自分の原稿で同じ手順を試すときの依頼文です。［ ］の中を書き換えて使えます。同じ文面を request.txt に置いています。

    PDF Creator の原典（https://github.com/daymade/claude-code-skills/tree/e37b50c323cf99471f18ac17a11c923bb96ce2ba/daymade-docs/pdf-creator）の SKILL.md と scripts/md_to_pdf.py を読み、次のMarkdownをPDFにしてください。

- 原稿：［Markdownファイルのパス］
- 用途：［例：会場で配る案内／スマートフォンで読む資料］
- 言語：［例：日本語］
- 版：［A4（warm-terra）／細いページ（mobile）／両方］
- フォント：［例：インストール済みの Noto Sans JP］

進め方：
1. 変換は原典のスクリプト（markdown_to_pdf）で行い、pandoc と Chrome を手作業でつなぐなどして変換処理を迂回しないでください。
2. 原稿・原典スクリプト・原典テーマは書き換えないでください。和文向けの調整が必要なら、原典CSSの後ろに足す追加CSSとして読み込み、その方法を記録してください。
3. 実際に使ったバックエンド（Generated: 行の backend=）、テーマ、フォント、各PDFのページ数を記録してください。
4. 全ページを画像で確認し、PDFから取り出した文字を原稿と照合してください（欠け・はみ出し・見出しの孤立・改ページ・括弧や句読点の位置）。
5. 表がある場合は、原典の指示どおり check_table_borders.py を実行してください。Chromeで出力したときは、同じテーマで WeasyPrint 出力した基準と --reference で比較してください。終了コード3は合格ではありません。
6. 確認できなかった環境（macOS のプレビュー、Adobe Acrobat Reader、実際の印刷など）と未確認の点を、確認済みの点と分けて報告してください。
