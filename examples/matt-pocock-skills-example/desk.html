      合成データ6件を見る（entries.json）

        依頼から仕様へ

        依頼の言葉は、読む人によって意味が変わります。作例では次のように決めました。決めたのは制作担当です。利用者への聞き取りや、仕様・テストの境界（seam）についての合意はしていません。

        依頼の言葉曖昧な点作例での決め方
        UIでもｕｉでもどこまでを同じ書き方とみなすかUnicode NFKC と小文字化で同じ形になるもの。ひらがなとカタカナ、誤字、同義語は含めない
        タグも見て表題のほかにどこを探すか表題とタグだけ。分野名と識別子は探さない
        言葉を足したら絞れて足した語はどう効くかすべての語を含むものだけ（AND）。語ごとに表題とタグのどちらにあってもよい
        分野でも選べる未選択・未知の分野のとき全分野なら絞らない。既知の分野は完全一致。未知の分野は0件

        用語は GLOSSARY.md（掲載項目・表題・タグ・分野・検索語・語・表記ゆれ など）、完成条件と受け入れ例は SPEC.md、元の依頼と事前の決定は input.md にあります。並べ替え、関連度順、一致箇所の強調、誤字の許容、型が不正な入力、速度や大きなデータは対象外です。

        失敗してから通す、3回の記録

        新しいテストを1件だけ足して実行し、期待した掲載項目と違うことで失敗するのを見てから、通るだけの変更をしました。下の数字は制作時に Node で実行した記録（tdd-history.json）から読んでいます。

          原典 tdd の「失敗を先に」「1回に1つ」「先回りしない」「整理し直しは繰り返しに含めない」を守りました。ただし原典が求める「テストの境界をテストの前に利用者と確認する」は行っていません。境界は制作担当が searchEntries(entries, query, {category}) の1つに事前に決めたもので、この作例は原典の手順を限定して使っています。

            Matt Pocock Skills（mattpocock/skills、固定コミット 49dd158d1076134a641b33efb035946536778336）の skills/engineering/domain-modeling/SKILL.md と GLOSSARY-FORMAT.md、skills/engineering/codebase-design/SKILL.md、skills/engineering/tdd/SKILL.md と tests.md・mocking.md を読んでから、既存の検索機能を直してください。

元の依頼：【例：UIでもｕｉでも探せて、タグも見てほしい。言葉を足したら絞れて、分野でも選べると便利。】
対象の関数とファイル：【例：search.mjs の searchEntries(entries, query, { category })】
テストの実行コマンド：【例：node --test search.test.mjs】

進め方：
1. 依頼の言葉のうち読み方が分かれるものを挙げ、GLOSSARY.md に用語として決めてください。実装の詳細は GLOSSARY.md に書かず、仕様の文書に書いてください。
2. 曖昧な点ごとに決め方と対象外を書き、データに対する期待値を、実装と同じ計算ではなく固定の値で書いてください。決められない点は推測で埋めず、私に質問してください。
3. テストを置く公開の境界（seam）を提案し、それぞれ捉えるものと捉えないものを1行で書いて、テストを書く前に私の確認を待ってください。
4. 確認したseamで新しいテストを1件だけ足して実行し、期待値の不一致で失敗することを確かめてから、通るだけの最小の変更をしてください。これを1段ずつ繰り返し、次の段を先回りして実装しないでください。整理し直し（リファクタリング）はこの繰り返しに含めず、別に提案してください。
5. 各段の実行コマンド、終了コード、テスト数・成功・失敗の数を、実際の出力から記録してください。

報告では、決めた用語と仕様、各段の失敗と成功の記録、変更したファイル、試していない入力と対象外を分けて書いてください。
