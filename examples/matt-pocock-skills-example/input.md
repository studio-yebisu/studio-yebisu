# 架空の既存検索を直す依頼

「UIでもｕｉでも探せて、タグも見てほしい。言葉を足したら絞れて、分野でも選べると便利。」

これはStudio Yebisuの記事用に作った架空の依頼・6件の合成データ・既存コードです。共有サイトの検索機能は変更しません。実在顧客への聞き取りや個別の仕様承認はしていません。

## 制作担当が事前に決める作例仕様（利用者からの追加回答ではない）

- 検索対象は title と tags のみ。categoryとidはキーワード検索に混ぜない。
- Unicode NFKC + 小文字化で英数字の全角/半角と大文字/小文字を同一視する。半角カタカナもNFKCで全角になる。ひらがなとカタカナの相互変換、誤字、同義語、形態素解析は対象外。
- 空白（全角空白を含む）で区切った語のすべてを含むAND検索。各語は同じフィールドにある必要はない。部分一致。
- category が all なら全分野、既存の分野名なら完全一致で絞る。未知分野は0件。
- 空語は全件または選択分野の全件。入力順を保ち、入力データを変更しない。
- 入力はこのデータ形状の有効な配列、文字列query、有効なoptions。型の不正入力は今回の範囲外。

## 事前に選んだテストのseam

唯一の対象: `searchEntries(entries, query, {category})`。
捉えるもの: 返るIDの集合と順序、空語・検索語・分野による選択。
捉えないもの: DOM表示、速度、巨大データ、ネットワーク、AIの正しさ、外部データ、利用者の好み。
この可逆的な作例の内部設計はユーザーの自律実行指示に基づき制作担当が確定した。上流tddのseamの確認をユーザーと対話したという実績にはしない。

## 小さな縦の実装（各段で新しいテスト1件→実際に失敗→最小の実装→実際に成功）

1. `ＵＩ` が `ui-notes,color-lab,motion-cards` を返す。表題とタグの正規化検索。
2. `UI　設計` が `ui-notes` だけを返す。前段で得た実コードにAND絞り込みを加える。
3. 空語、category slides が `slide-story,slide-layout` を返す。前段の実コードに分野絞り込みを加える。

既存の空語テストを保つ。将来の段の実装を先回りしない。各失敗はassertionの期待ID不一致として観測し、構文エラーや未実装importをREDの証拠にしない。
