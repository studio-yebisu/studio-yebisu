# 作例検索の修正仕様（架空・作例用）

## この文書の位置づけ

- 元の依頼は記事用に作った架空の一文です。実在顧客への聞き取り、利用者による仕様承認、seamの対話確認はしていません。
- 下記の「確定した受け入れ条件」は、利用者の自律実行指示のもとで制作担当が事前に決めた作例仕様（`input.md`）を、曖昧さが残らない形に書き直したものです。利用者からの追加回答ではありません。
- この文脈の言葉は `GLOSSARY.md` に従います。

## 依頼文の曖昧さと、作例としての決め方

| 依頼の言葉 | 曖昧な点 | 作例での決め方 |
| --- | --- | --- |
| 「UIでもｕｉでも探せて」 | どこまでの書き分けを同じとみなすか | Unicode NFKCと小文字化で同じ形になる表記を同一視する。半角カタカナもNFKCで全角になる。ひらがなとカタカナの相互変換、誤字、同義語は含めない |
| 「タグも見てほしい」 | 表題以外にどこを探すか | 表題とタグだけ。分野名と識別子は検索語の対象にしない |
| 「言葉を足したら絞れて」 | 足した語はどう効くか | すべての語を含む掲載項目だけを残す。語ごとに表題とタグのどちらにあってもよい |
| 「分野でも選べる」 | 未知の分野、未選択のとき | 全分野なら絞らない。既知の分野は完全一致。未知の分野は0件 |

## 確定した受け入れ条件

1. 検索語が空、または空白だけで語が1つもないときは、全分野なら全件、分野を選んでいればその分野の全件を返す。
2. 各語は、掲載項目の表題またはタグのどこかに部分的に含まれれば一致とみなす。
3. Unicode NFKCと小文字化で同じ形になる表記を同じ書き方として扱う。例: `ＵＩ`、`ui`、`Ui` は `UI` と一致する。
4. 語の区切りは半角空白と全角空白の両方。連続した空白は1つの区切りとみなす。
5. 複数の語はAND。すべての語が一致した掲載項目だけを返す。
6. 分野の指定は検索語による選択と同時に効く。
7. 結果は元の掲載順を保ち、渡された作例集を変更しない。

## 受け入れ例（合成データ6件に対する期待値）

| 検索語 | 分野 | 期待する掲載項目（順序どおり） | 段 |
| --- | --- | --- | --- |
| `` | 全分野 | `ui-notes, color-lab, slide-story, slide-layout, motion-cards, agent-check` | 既存 |
| `ＵＩ` | 全分野 | `ui-notes, color-lab, motion-cards` | 1 |
| `UI　設計` | 全分野 | `ui-notes` | 2 |
| `` | slides | `slide-story, slide-layout` | 3 |

期待値は合成データと事前仕様を制作工程が読んで定めた固定値です。実装と同じ計算で導いた値ではありません。

## 対象外（今回は決めない、作らない）

- ひらがな/カタカナの同一視、誤字の許容、同義語、形態素解析、読み仮名検索
- 結果の並べ替え、関連度順、一致箇所の強調表示
- 型が不正な入力（配列でない作例集、文字列でない検索語、不正なoptions）の扱い
- 画面表示、URLへの検索状態の保存、速度、巨大データ、ネットワーク、外部データ
- 共有サイトの検索機能そのもの

## テストのseam

- 唯一の対象: `searchEntries(entries, query, { category })`
- 捉えるもの: 返る掲載項目の識別子の集合と順序。空の検索語、語、分野による選択。
- 捉えないもの: DOM表示、速度、巨大データ、ネットワーク、AIの正しさ、外部データ、利用者の好み。
- このseamは制作担当が事前に1つだけ選んだもので、利用者と対話して合意したものではありません。

## 進め方

`input.md` の3段を、各段「新しいテスト1件 → 実際の失敗を観測 → 最小の実装 → 実際の成功を観測」で進めます。テストの実行は親の制作工程が行い、その実出力だけを記録します。
