# Chatterbox（英語オリジナル版）ローカル音声合成 — 実装計画

> **状態：実装計画（未実行）。** この文書と `run_example.py`・`inputs/jobs.json` は claude-opus-5-5 が作成しました。作成者は推論を実行しておらず、音声も聴いていません。オペレーターの実行記録（`progress.json`・`results.json`）ができるまで、ここに書かれた出力・数値・合否はすべて予定です。

## 目的と範囲

- resemble-ai/chatterbox の**英語オリジナル版 `ChatterboxTTS`**（`src/chatterbox/tts.py`）を、元の Python API のまま手元で 3 回だけ動かす。Multilingual・Turbo・Nano は使いません。
- 話者条件はチェックポイント付属の `conds.pt`（組み込み条件）だけを使います。`audio_prompt_path=None` とし、参照音声・人の声・声のクローン・マイク・音声認識は使いません。
- 生成された WAV は「動作を確かめたツール出力」です。サイトの解説ナレーションや音声ガイドには使いません。
- 後で作る構造図の材料として、実際に作られたファイルと実測値を固定するのが目的です。新しいモデル、ホスト型 API、SKILL.md、音声アシスタントは作りません。

## 実際の処理経路（ソースに基づく説明）

1. **テキスト正規化** — `punc_norm` で先頭を大文字にし、空白をまとめ、珍しい句読点を置き換え、文末記号がなければ `.` を付けます。
2. **テキストトークン化** — `EnTokenizer`（`tokenizer.json`）で空白を `[SPACE]` に置き換えてから ID 列にします。`cfg_weight > 0` なら同じ行を 2 本にして、先頭に開始トークン 255、末尾に終了トークン 0 を付けます。
3. **組み込み条件** — `conds.pt` から読み込んだ `Conditionals` です。T3 側は話者埋め込み、プロンプト音声トークン、`emotion_adv` を持ちます。`exaggeration` が保存値と違えば、`generate` が `emotion_adv` だけを作り直します。S3Gen 側はプロンプトトークン、プロンプトのメル特徴、x-vector 埋め込みを持ちます。
4. **T3 による自己回帰生成** — Llama 系 520M 構成のバックボーンに、条件・テキスト・音声トークンの埋め込みを並べて入れます。CFG の 2 行（条件付きと、テキスト埋め込みをゼロにした行）からロジットを合成し、repetition penalty → temperature → min_p → top_p の順で処理してから多項分布で 1 トークンずつサンプリングします。停止トークン 6562 が出るか、`max_new_tokens=1000` に達したら止まります。
5. **無効トークンの除去** — 条件付き行だけを取り出し、`drop_invalid_tokens` で開始・終了トークンの範囲を切り出してから、`< 6561` の ID だけを残します。
6. **S3Gen** — 音声トークンを Upsample Conformer エンコーダーに通し、条件付きフローマッチング（CFM、10 ステップ。初期ノイズは乱数）でメルスペクトログラムにします。続いて HiFT ボコーダー（F0 予測付き）で 24 kHz の波形にし、先頭 40 ms に無音とフェードインをかけます。
7. **Perth 透かし** — `perth.PerthImplicitWatermarker.apply_watermark` が、振幅スペクトルに神経網で透かしを埋め込み、元の位相と組み合わせて波形に戻します。`generate` が返すのはこの透かし入りの音声です。
8. **PCM16 WAV** — ランナーが返り値を `[-1, 1]` にクリップし、×32767 して丸め、int16 にしたうえで soundfile で mono PCM16 WAV（`model.sr`。24000 を想定し、実際の値を確認）として保存します。正規化・トリミング・時間伸縮・透かし除去はしません。

`VoiceEncoder` と参照音声の経路（`prepare_conditionals`）もコードにはあり、`from_local` は VE の重みを読み込みます。ただし今回は呼び出しません。

## 3 つの試行（`inputs/jobs.json`）

| ID | テキスト | exaggeration / cfg_weight | 意図 |
| --- | --- | --- | --- |
| `default` | 2 文・22 語の英語（生活上の案内） | 0.5 / 0.5 | 上流の既定値で合成する |
| `expressive` | `default` と同じ文、同じ seed | 0.8 / 0.3 | **2 つの設定を同時に変えた対の比較** |
| `second` | 別の 2 文・18 語の英語（移動の案内） | 0.5 / 0.5 | 別の文を既定値で合成する |

全ジョブ共通の設定：`seed=20261019`、`temperature=0.8`、`repetition_penalty=1.2`、`min_p=0.05`、`top_p=1.0`、`audio_prompt_path=null`。人名・有名人・団体の声は使いません。

- 各ジョブは**一度だけ**、表の順に、同じ 1 つのモデルで `generate` します。良いものを選ぶための再生成や、記録に残らない再生成はしません。
- `expressive` は 2 つの値を同時に変えているので、差をどちらか一方の効果とは言えません。品質や感情表現の証拠にもなりません。
- 上流の `generate` は `conds.t3` を作り直したりプロンプト埋め込みをキャッシュしたりするため、ジョブの順番によってモデルの状態が引き継がれます。元の API の挙動なので、そのまま記録します。

## コマンド（オペレーターが実行）

```text
python run_example.py --checkpoints <CHECKPOINT_DIR> --out <NEW_OUT_DIR> --device cuda [--threads 4] [--jobs <JOBS_JSON>]
```

- `<CHECKPOINT_DIR>`：`ve.safetensors`・`t3_cfg.safetensors`・`s3gen.safetensors`・`tokenizer.json`・`conds.pt` の 5 ファイルが入ったディレクトリ。ランナーはダウンロードしません。
- `<NEW_OUT_DIR>`：新しいディレクトリか、空のディレクトリ。中にファイルがあれば停止します。
- `--device` は必須です。CUDA が使えないときは、何をすればよいかを示すエラーで止まり、CPU に自動で切り替えることはありません。CPU で試す場合は、`--device cpu` と別の `--out` を指定した、独立した試行として記録します。
- Python 3.11 が必要です。起動直後に `HF_HUB_OFFLINE=1`・`TRANSFORMERS_OFFLINE=1`・`HF_HUB_DISABLE_IMPLICIT_TOKEN=1` を設定します。インストール、サブプロセス、認証情報の読み込みはしません。

### 読み込み前の検証

ジョブの ID・本文・語数・2 文であること・seed・設定値、5 つのチェックポイントファイル、インストールされた `chatterbox` パッケージの全 `.py` が `runtime/upstream-pins.json` の SHA-256 と一致すること、`chatterbox-tts==0.1.7` であることを確かめます。Perth は手元の固定版ソースと 4 ファイルを照合し、インストール時のメタデータにコミット ID があればそれも照合します。読み込み後は、モデルが `PerthImplicitWatermarker` を使っていること（`DummyWatermarker` や透かしの無効化は認めない）、`conds` があること、`sr == 24000` であること、英語専用の T3 構成であることを確かめます。

### 出力（予定）

- `audio/default.wav`・`audio/expressive.wav`・`audio/second.wav`：透かし入りの mono PCM16 WAV
- `progress.json`：段階ごとにアトミックに更新します。失敗したときも、それまでのファイルは残し、`failed` と段階・例外の種類を記録します（個人のパスは置き換えます）。
- `results.json`：3 ジョブがすべて保存された後にだけ書きます。`status: "passed"` になるのは、全チェック（呼び出しが各 1 回、ハッシュの連鎖、PCM16・mono・サンプルレート・フレーム数・読み戻し時の一致・無音でないこと）が通ったときだけです。

## 実測とソース説明の区別

- **実測**（実行後に `results.json` に入る予定）：正規化後のテキスト、T3 が受け取ったテキストトークン ID、T3 が返したフィルター前の音声トークン ID、S3Gen が受け取ったフィルター後の ID と件数、S3Gen 出力・透かし前後の形状・統計・SHA-256、返り値のテンソルと WAV のハッシュ・サンプル数・長さ・ピーク・RMS・クリップした数、各呼び出しの実時間。
- 計測には、`t3.inference`・`s3gen.inference`・`watermarker.apply_watermark` の各インスタンスに通過型のプローブをかぶせます。元の関数を 1 回ずつ呼び、入力も出力も変えず、ジョブごとに `finally` で外します。追加の推論はしません。
- **ソースに基づく説明だけ**のもの：注意重み、確率分布、CFM の途中経過、ボコーダー内部、透かしのビット。これらは記録しないので、図にするときは「ソースに基づく説明」と明記します。
- 時間は 1 回だけの実測値で、ベンチマークや速度の保証ではありません。同じ seed でも、GPU やソフトウェアのバージョンが違えば同じ音声になるとは限りません。
