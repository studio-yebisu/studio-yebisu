LiveTalkingは、声の入力・アバター・音声合成・出力口を名前でつなぐPythonのエンジンです。1つのAIモデルでも、ホスト型APIでも、SKILL.mdでもありません。この作例は、その中の MuseTalk の経路（MuseReal・WhisperASR・BaseAvatar）だけを、制作担当が1回だけ実行しました。

渡したのは、以前の作例と同じバイトの肖像1枚（《モナ・リザ》の複製画）と、以前の作例の既存の英語TTSのWAV 2本です。新しく合成・録音した音声や、新しく作った人物ではありません。顔は手動の枠 — で切り出し、検出器は使っていません。

潜在と声の特徴がU-Netで1回ずつ合流し、顔の部分と生の音2片が組になります。待機のコマは元の画像、声のコマは貼り戻しです。2本で—コマ（貼り戻し—・元画像—）が返り、U-Netの予測は—枚でした。数はどれも実測で、互いに等しいとは仮定していません。

実行の記録（制作担当の1回）
照合する—ファイル

開くたびに、一覧の固定 SHA-256 と、各ファイルの大きさと SHA-256 を確かめます。原典の8引用の行、記録どうしの数と ID、PNG・WAV の形式、MP4 の映像と音声のトラックも照合します。1つでも違えば、図・動画・音声・保存を止めます。

    できないこと・確かめていないこと
    • 人の耳での聴取、口の動きと音の同期の正確さ、自然さ、本人らしさ、見た目の承認は確かめていません。MP4 や WAV が保存できることは同期の証拠ではありません。
    • リアルタイム性能は測っていません。時間は CPU・float32 での1回の観測です。図と解説動画の動きや32秒の時刻も説明のためで、処理時間ではありません。
    • 実行していないもの：app.py・HTTP サーバー・WebRTC の接続・RTMP・仮想カメラ、LLM・新しい TTS・声のクローン・文字起こし、Wav2Lip・UltraLight・ernerf、顔検出・顔の解析・MuseTalk の genavatar、ComfyUI。EdgeTTS は原典が作りましたが、文を1つも渡していません。
    • 捕捉は原典の WebRTCOutput の受け手を Disk捕捉 にした有限の区間で、新しい MP4 生成の API ではありません。捕捉の外へ押し出されたコマと片は数えて記録し、MP4 には入れていません。
    • 入力の WAV は以前の Chatterbox の作例の出力で、元の合成で Perth の透かしが入っています。この変換と圧縮の後に透かしを検出できるかは確かめていません。
    • ほかの画像や音声での動きは確かめていません。ランナーは今回の2つの WAV・肖像・ジョブのハッシュ、手動の枠とマスク、捕捉の条件を照合して止まるように書かれています。
    • 同梱した原典は選んだ27ファイルで、ランナーが照合する23パスをすべて含みますが、アプリ全体ではありません。重み・依存・FFmpeg は別に必要です。実制作は全177ファイルの checkout で、同梱分だけでの再実行はしていません。
    • 作者の執筆後、制作担当がこの図・ページ・編集ソースと無音紹介動画を実際に表示・描画・再生して確認しました。範囲は visual-verification.json に記録しています。人の聴取・同期精度・審美的承認、実機iOS/Safari/VoiceOver・200%拡大は未確認です。
    記録の言い違いと、今の読み方
    • 第1段階のメモとランナー、診断PNGの保存名は「upper-half-masked」と書いていますが、実際の画素と原典の VAE は下半分を黒くします。ファイルと名前はそのまま保全し、この図は正しい向きで描きます。新しい推論や修正ではありません。
    • 結果の待ち行列は貼り戻しの前です。予測した顔の部分と生の音2片が組になり、その後の process_frames が元画像か貼り戻しを選び、透かしを描きます。
    • 待機の片（type 1）は、入力の待ち行列が空のときに原典が作るゼロの音です。WAV の中の無音を判定したものではありません。Whisper の符号器は待機の音でも動き、全部が待機のバッチでは U-Net を省きます。
    • 詳しくは SOURCE-NOTES.md（制作担当の追記）。
