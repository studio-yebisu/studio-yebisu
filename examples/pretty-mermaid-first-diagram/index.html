図を文章で読む

Pretty Mermaid は、AIが読むMarkdownの指示書・参照資料と、手元で動くNode CLIの組み合わせです。AIのモデル、APIやクラウドのサービス、ブラウザーで描く仕組み、自動で全部を進める道具ではありません。

  1. 中身　SKILL.md に7つの手順と、図の種類・出力形式・テーマ・書き方・確認の指針があります。参照資料は DIAGRAM_TYPES.md・THEMES.md・api_reference.md の3件です。元の記述では構文とテーマを参照し、API資料の直接呼び出しは適用していません。
  2. AIへ渡すもの　指示書と架空の依頼（図の種類・目的・用語・関係・出力・テーマ）を同じ作者AIへ渡しました。元の制作では Opus 5.5 が1回の依頼で、流れ図・やり取り・状態の3つの .mmd を書きました。
  3. 作者AIがしたこと　指示書に沿って短いラベル・条件のラベル・戻り道を選び、用語と関係を残した記述を保存しました。作者AIはCLIを実行していません。
  4. 制作担当がしたこと　同じ .mmd と設定を、固定版の node scripts/render.mjs へ12回渡しました（3つの記述 × 4つの出力）。
  5. CLIの中　.mmd を読み、beautiful-mermaid の renderMermaidSVG がテーマとフォントを付けたSVGを作ります。PNGは同じSVGを png.mjs でCSSを整えてから Resvg で幅1200に画像化します。文字図はSVGの写しではなく、renderMermaidASCII の別経路でUnicodeの罫線を使って書き出します。ブラウザーやDOMは使いません。
  6. 受け取ったもの　1つの記述につき、github-light のSVG、github-dark のSVG、github-light のPNG（幅1200）、色なしの文字図の4つ。明暗のSVGは同じ関係と名前を持ちます。
  7. 読んで照合　制作担当が別工程で、12回の正常終了、空でないSVGが <svg で始まること、PNGが開けること、文字図に図が出ていることを確かめ、日本語のラベル・矢印の向き・条件を原文と見比べました（関係は5・5・6本）。すべての意味を自動で保証するものでも、人の承認でもありません。
  8. 次の使い方　直すときは .mmd、資料や拡大にはSVG、共有にはPNG、端末には文字図。元の読み比べ画面で、記述と出力を並べて読めます。

6つの部品は、この図解のための整理です。原典に共通の決まった構造があるわけではありません。
