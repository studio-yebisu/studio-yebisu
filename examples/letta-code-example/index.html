        この作例で確かめた範囲
        
    Letta Code の記憶は Markdown のファイルと Git で管理されます。ルートの MEMORY.md から、フォルダーごとの案内（MEMORY.md）を通って詳細のメモを読む形です。記憶を変えて commit するとき、Git の pre-commit で原典の検査が動き、形が決まりに合わなければ commit を止めます。この作例は、その「保存の前の形の点検」だけを試したものです。
    
        
    8件のうち2件が保存され、6件が意図した理由で止まりました。止まった件では HEAD は基準の commit のままで、stage の変更は消えずに残りました。L03 は、L02 と同じ変更から案内（bookclub/MEMORY.md）だけを残した入力を、別の新しいリポジトリで試した記録です。ページの上でその場で直したものではありません。
    
        
    L04 は 901文字のメモ（架空の上限 900文字）、L06 はルートの合計 1201文字（上限 1200文字）で止まった記録で、上限ちょうどの 900文字・1200文字は試していません。L08 では検査API（実行前の初期方針で検査）の指摘は0件でしたが、原典の検査スクリプトが .memfs.config.json の変更を人の承認なしでは認めず、止めました。
    
        
    形の点検を通ることは、記憶の中身が正しい・事実として正確・採用してよい、という意味ではありません。人の承認やセキュリティの保証でもありません。エージェントとの会話、モデルの推論、記憶の自動抽出や想起、Letta Cloud・ログイン・同期、/init と履歴の調査は使っていません。架空の記憶と初期方針は制作側が実行前に固定したもので、実在の人の記憶や、実際に採用された方針ではありません。
    
        
    確認：記録の自動確認208件、制作側が別に書いた8つの Git リポジトリと原典 hook の照合（independent-checks.json）、別のコピー・新しい Node・新しい Git で記録の全バイトが一致（reproduction-checks.json）。実機の iPhone・Safari での確認と、人による内容の承認は記録にありません。
